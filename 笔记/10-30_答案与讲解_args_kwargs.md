## 第 1 题 · args 和 kwargs 到底是什么类型？

**实际输出（实跑）：**
```
固定参数: 1 2
多余位置参数: (3, 4, 5)
关键字参数: {'x': 10, 'y': 20}
```

**① 输出：**（见上）

**③ 解释：**

> - `args` 是**元组（tuple）** —— `(3, 4, 5)`
> - `kwargs` 是**字典（dict）** —— `{'x': 10, 'y': 20}`
>
> **为什么 `x=10` 不进 args？**
> 因为**位置参数**和**关键字参数**在 Python 里是**两条完全不同的通道**：
>
> | 调用形式 | 归谁管 |
> |---|---|
> | `f(1, 2, 3, 4, 5)` —— 裸值 | 位置参数 → 先填 `a`/`b`，剩下的进 `*args` |
> | `f(x=10, y=20)` —— 带 `=` | 关键字参数 → 进 `**kwargs` |
>
> `x=10` 带了 `=`，所以它**从一开始就不是位置参数**，
> 根本没资格进 `args`。**args 只装「没有名字的值」。**

> 📌 **记这个对应关系就够了：**
> **`*args` 收「裸值」→ 元组；`**kwargs` 收「带名值」→ 字典。**

## 第 2 题 · 定义处 vs 调用处

**实际输出（实跑）：**
```
g(*数据, **选项):
  args = (1, 2, 3)
  kwargs = {'x': 10, 'y': 20}

g(数据, 选项):
  args = ([1, 2, 3], {'x': 10, 'y': 20})
  kwargs = {}
```

**② 解释 —— 这是今天最核心的一题：**

> **同一个星号，在两个位置是两回事：**
>
> | 位置 | `*` 的动作 | 比喻 |
> |---|---|---|
> | **定义处** `def g(*args)` | **打包** | 拿口袋把散落的豆子装起来 |
> | **调用处** `g(*数据)` | **拆包** | 把口袋里的豆子倒出来，一个一个摆 |
>
> **所以：定义处是「打包」，调用处是「拆包」。**
> `**` 完全同理：
> - 定义处 `**kwargs` = 把散落的键值对**打包成字典**
> - 调用处 `**选项` = 把字典**拆开成一个个关键字参数**
>
> 你自己那份 `练习/星号到底改了什么.py` 用的就是
> **「插座 vs 口袋」**这个比喻 —— 口袋是收集（定义处），
> 插座是插入（调用处）。

**为什么 `g(数据, 选项)` 不一样？**

> 因为不加星号，Python 看到的是**两个普通的位置参数**：
> 一个列表、一个字典。
> 它们**各自整体**被当成一个值塞进 `args`。
>
> ```
> g(*数据, **选项)  →  数据被拆成 1, 2, 3 三个值
>                     选项被拆成 x=10, y=20 两个关键字
>
> g(数据, 选项)    →  数据整体是一个值 → args = ([1,2,3], {...})
>                     选项整体是一个值 → 也进 args
> ```
>
> **一句话：加星号 = 拆开；不加 = 整体。**

## 第 3 题 · my_sum

```python
def my_sum(*args):
    """求所有数字的和。"""
    total = 0
    for n in args:
        total += n
    return total
```

**实跑：**
```
my_sum(1, 2, 3)        → 6
my_sum(1, 2, 3, 4, 5)  → 15
my_sum(10)             → 10
my_sum()               → 0
my_sum(-1, 1)          → 0
```

**② `my_sum()` 返回 0** —— 因为 `args` 是空元组，循环一次都不进，`total` 保持初值 0。

**③ 为什么必须用 `*args`：**

> 因为**参数个数不确定**。
> 写成 `def my_sum(a, b, c)` 就固定成 3 个了，
> 传 1 个会报 `TypeError: missing 2 required positional arguments`。
>
> 普通参数**每一个都是必填的**（除非给默认值），
> `*args` 则是「**收多少都行，一个不收也行**」。

> 📌 **注意 `total = 0` 这行不能省**（E02 复习）：
> 累加器必须**初始化**。空元组时循环不执行，
> 不初始化就会在 `return total` 处报 `NameError`。

## 第 4 题 · show_info

```python
def show_info(**kwargs):
    """遍历 kwargs，把每个 "键: 值" 打印出来。"""
    for k, v in kwargs.items():
        print(f"{k}: {v}")
```

**实跑：**
```
name: 小明
age: 20
```

**② 为什么必须用 `**kwargs`：**

> 因为调用方要传的是**「名字 + 值」**，不是「一串值」。
> `show_info(name="小明", age=20)` 里的 `name=`、`age=` 就是**关键字参数**，
> 只有 `**kwargs` 能收。
>
> 如果写成普通参数 `def show_info(name, age)`，
> 那就**强制你必须传这两个**，多一个少一个都不行 —— 这就失去了灵活性。

**③ 「只打印指定的那几个键」怎么做：**

```python
def show_info(要打印的键=None, **kwargs):
    """只打印指定的那几个键；不指定就全打印。"""
    if 要打印的键 is None:
        for k, v in kwargs.items():
            print(f"{k}: {v}")
    else:
        for k in 要打印的键:            # 遍历【要打印的键】这个列表
            if k in kwargs:             # 字典里【确实有】这个键才打印
                print(f"{k}: {kwargs[k]}")
```

用法：
```python
show_info(name="小明", age=20, 城市="广州")
show_info(["name", "城市"], name="小明", age=20, 城市="广州")
# → name: 小明
# → 城市: 广州
```

**要点：**
1. **参数顺序是 `要打印的键=None, **kwargs`** ——
   普通参数必须在 `**kwargs` **前面**（`语法` 要求）
2. `if k in kwargs:` 这个检查**必须有** ——
   要打印的键里可能有一个 kwargs 里根本没有（E25 同款坑：`in` 用于字典是查键）

> 📌 **这就是「关键字专用参数」（keyword-only）的写法**：
> `def f(普通参数, *args, 仅关键字参数=None, **kwargs)`
> 星号之后的参数**只能按名字传**。
> 这是 Python 里做「可选配置」的常用套路。

## 第 5 题 · 汇总配送单

```python
def 汇总配送单(园所名, *菜单, **附加):
    """汇总配送单。"""
    print(f"园所：{园所名}")
    print(f"菜单：{'、'.join(菜单) if 菜单 else '（无菜单）'}")
    附加文本 = " ".join(f"{k}={v}" for k, v in 附加.items())
    print(f"附加：{附加文本 if 附加文本 else '（无）'}")
```

**实跑：**
```
园所：阳光幼儿园
菜单：红烧肉、青菜、米饭
附加：配送日期=2026-10-30
```
```
园所：阳光幼儿园
菜单：（无菜单）
附加：（无）
```

**② 为什么「园所名」是普通参数，「菜单」是 `*args`：**

> 因为**两者的「个数确定性」不同**：
>
> | | 个数 | 为什么 |
> |---|---|---|
> | 园所名 | **永远 1 个** | 一张配送单只对应一个园所 —— 这是【业务约束】 |
> | 菜单 | **不固定** | 3 个菜、5 个菜、0 个菜都可能 —— 这是【数据现实】 |
>
> 如果菜单也写成普通参数 `def 汇总配送单(园所名, 菜单1, 菜单2, 菜单3)`，
> 就回到 `加五个` 那个老问题了 —— **签名被写死**，
> 加第 4 个菜就得改函数签名，改了签名所有调用点都得跟着改。
>
> **这就是 `*args` 存在的意义：让「个数不定」这件事，
> 由调用方自由决定，而不是由函数签名决定。**

**③ 菜单为空时打印「（无菜单）」：**

```python
菜单文本 = "、".join(菜单) if 菜单 else "（无菜单）"
```

> ⚠️ **这里有个坑要注意**：`if 菜单` 判断的是**空列表**。
> `*args` 收集到的是**元组**，空元组 `()` 在 `if` 里也是假值 —— 所以能正常工作。
> （和 E25 一样，`if 元组` 判断的是「是不是空的」）

## 第 6 题 · 签名里的位置

**实际输出（实跑）：**

```
h(1, 2, 3):
  a = 1 b = 2
  args = (3,)
  kwargs = {}

h(1, 2, 3, x=1):
  a = 1 b = 2
  args = (3,)
  kwargs = {'x': 1}
```

**③ `h(1, 2, x=1, 3)` → 报错：**
```
SyntaxError: positional argument follows keyword argument
```
（中文意思：**位置参数不能跟在关键字参数后面**）

**为什么？**

> 因为 Python 解析调用时是**从左往右**的。
> 看到 `x=1` 就知道「x 这个名字已经被占了」，
> 后面再出现一个**没有名字的裸值**，Python 无法判断：
> 这个 `3` 是要填给 `a`？`b`？`args`？`kwargs`？
> —— **顺序上它已经错过了所有具名参数的位置**。
>
> 所以这不是「运行时检查」，而是**语法期就拒绝**。

**改成 `h(1, 2, 3, x=1)` 就好了** —— 裸值全在前面，带名的全在后面。

> 📌 **记忆：调用时也是「先位置，后关键字」。**
> 这和你在 `todo_cli.py` 里写的 `show_info(name="小明", age=20)` 是同一个规则。

## 第 7 题 · 默认值 + *args 怎么分工

**实际输出（实跑）：**
```
k():
  a = 0 b = 0
  args = ()

k(1, 2):
  a = 1 b = 2
  args = ()

k(1, 2, 3):
  a = 1 b = 2
  args = (3,)

k(1):
  a = 1 b = 0
  args = ()
```

**⑥ 解释：**

> **默认值只在「这个参数没被传值」时才生效。**
>
> Python 的分工顺序是**从左往右按位置填**：
>
> ```
> k(1, 2, 3)
>    ↑  ↑  ↑
>    a  b  args
> ```
>
> 第 1 个值 → `a`，第 2 个值 → `b`，第 3 个值 → **`args`**。
> **默认值根本没有参与**，因为 `a` 和 `b` 都被实参填满了。
>
> ```
> k(1)
>    ↑
>    a  → b 没传值 → 用默认值 0 → args 空
> ```
>
> **所以：**
> - **默认值**管的是「**参数不够时**用哪个值兜底」
> - **`*args`** 管的是「**参数多了时**往哪放」
>
> **它们是「不够」和「太多」两件事，永远不冲突。**

> ⚠️ **你原本的直觉是错的**：
> 「有默认值了 → 实参会先被默认值吃掉 → `*args` 收不到」。
> 实际相反：**实参永远优先**。

> 📌 **这题的真正价值在于「预测」**：
> 如果你在跑之前预测成 `args = ()`，跑完发现是 `(3,)` ——
> 那说明你的「参数怎么分配」模型还没建好。
> **这种「预测错」比「做错题」更值得停 30 秒想清楚。**

## 第 7.5 题 · 位置参数陷阱

**① 预测：`f(1, 2, x=1, 3)` → 报错**
```
SyntaxError: positional argument follows keyword argument
```

**② 解释：** 见第 6 题③。
`f(1, 2, 3, x=1)` 合法 —— **裸值全在前面，带名的全在后面**。

**③ 为什么这种错误是「好事」？**

> 因为它是**当场炸给你看**的语法错误，不是静默错误。
>
> 联系你 10-29 的批改结论：
> **「错的东西有时比对的更安全」**
> - 「漏写 `return`」→ 静默，不报错，结果错，一周都发现不了
> - 「拼错 `ruturn`」→ 当场 `NameError`，一眼看见
>
> `f(1, 2, x=1, 3)` 属于**后者** ——
> Python 在**编译期**就拒绝执行，**根本不会带着这个 bug 跑起来**。
>
> **语法错误是 Python 免费送给你的检查。**
> 你要担心的是那些「跑得好好的，结果是错的」——
> 那才是真正的静默错误。

## 第 8 题 · 综合：日志记录器

```python
def log(级别, 消息, *标签, **额外字段):
    """日志记录器。"""
    部分 = [f"[{级别}] {消息}"]
    if 标签:
        部分.append("标签: " + ", ".join(标签))
    if 额外字段:
        部分.append("字段: " + ", ".join(f"{k}={v}" for k, v in 额外字段.items()))
    print(" | ".join(部分))
```

**实跑（4 种组合全部验证）：**
```
[INFO] 启动成功 | 标签: 系统, 启动
[ERROR] 磁盘满了
[WARN] 响应变慢 | 标签: 网络 | 字段: 耗时=3.2
[DEBUG] 调试信息 | 标签: 模块 | 字段: 用户=小明, 耗时=0.1
```

**② 边界处理：**

> 用 `if 标签:` / `if 额外字段:` **判断存在性**，
> 存在才拼上去，**不存在整段省略**（而不是显示「无」）。
>
> **为什么这样设计？**
> 日志是给人看的。日志里出现 `标签: 无 | 字段: 无` 这种噪音，
> 反而让真正有信息的行被淹没。
> **信息密度 > 格式统一。**

**③ 跑 4 种组合验证** —— 见上面输出。

> 📌 **这题把今天的概念全用上了：**
> - 固定参数（级别、消息）→ 必填的普通参数
> - `*标签` → 数量不定的**裸值**
> - `**额外字段` → 数量不定的**键值对**
> - `if 标签:` → **空元组是假值**（E25 同款判断）
> - `", ".join(...)` → **元组和字典都能遍历出字符串**

## 九、这 8 题串起来的一张表

| 位置 | 写法 | 动作 | 收成什么 |
|---|---|---|---|
| **定义处** | `*args` | 打包（收集裸值） | 元组 `tuple` |
| **定义处** | `**kwargs` | 打包（收集键值对） | 字典 `dict` |
| **调用处** | `f(*列表)` | 拆包（拆成裸值） | 一堆位置参数 |
| **调用处** | `f(**字典)` | 拆包（拆成键值对） | 一堆关键字参数 |

> 📌 **一句话总纲：**
> **定义处 `*` = 收集，调用处 `*` = 展开。**
> `**` 同理，只是收集/展开的是「键值对」。
