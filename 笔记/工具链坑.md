## T03 · 「网页打不开」不等于「git 推不上去」—— 两条通道要分开测

| 项 | 内容 |
|---|---|
| 踩过次数 | **2** |
| 标签 | 网络、排查、GitHub |
| 第一次 | 2026-10-27 |
| 最近一次 | 2026-10-27 |

**症状（当时看到什么）**

```text
浏览器打开 GitHub 经常崩，以为推不上；但实测 git ls-remote 却能成功。反过来也有：git 偶尔超时，浏览器却是好的。
```

**原因（为什么会这样）**

网页和 git 走不同的 CDN 边缘节点，成功率完全不一样。实测同一时段：网页 github.com/login 0-40%，git 的 info/refs?service= 6 个 IP 全部 10/10 = 100%。根因是校园网随机丢弃 TCP 443（ICMP 通但 TCP 握手超时），git 有重试所以稳得多。

**解法（怎么解决）**

- 两条通道分开测：网页用 github.com/login，git 用 <仓库>.git/info/refs?service=git-upload-pack
别用网页表现推断 git —— 测完再决定要不要改道
- 补充：push.sh 里做成 5 轮 × 6 IP 自动重试，通道不稳时能自动换 IP

## T01 · git http.curloptResolve 是单值键，多次设置互相覆盖

| 项 | 内容 |
|---|---|
| 踩过次数 | **1** |
| 标签 | git、配置 |
| 第一次 | 2026-10-27 |
| 最近一次 | 2026-10-27 |

**症状（当时看到什么）**

```text
给 4 个域名各设了一次 http.https://<域名>/.curloptResolve，结果 git config --get-regexp 查出来只剩最后一条。github.com 能连通，但 api/codeload/objects 全部失败。
```

**原因（为什么会这样）**

http.curloptResolve（不带 URL 前缀）是单值键，后设的直接覆盖前面的。必须用带 URL 前缀的 http.https://<域名>/.curloptResolve，那种是 URL 级配置，可多值共存。

**解法（怎么解决）**

- git config --global http.https://github.com/.curloptResolve "github.com:443:20.27.177.113"  （四个域名各一条）
验证：git config --global --get-regexp curloptResolve 应该看到 4 条

## T02 · push 报「空输出 exit=0」其实是 Credential Manager 在等弹窗

| 项 | 内容 |
|---|---|
| 踩过次数 | **1** |
| 标签 | git、认证、排查 |
| 第一次 | 2026-10-27 |
| 最近一次 | 2026-10-27 |

**症状（当时看到什么）**

```text
git push 没报错也没输出，exit code 是 0，看着像成功了。但 git ls-remote --heads origin 查远端还是空的。加 GIT_TRACE=1 才看到最后一行停在：run_command: 'git credential-manager get'
```

**原因（为什么会这样）**

Credential Manager 会弹图形界面问用户名密码，无 GUI 环境里弹不出来，进程就一直等。这是认证问题，但表现像网络问题，极具误导性。

**解法（怎么解决）**

- git config --global credential.interactive never
排查：GIT_TRACE=1 git push > log 2>&1 看停在哪一行
bash 里 git 的输出可能被吞，必须重定向到文件再读

## T04 · ICMP 通不代表 TCP 通：ping 123ms 但 curl 握手超时

| 项 | 内容 |
|---|---|
| 踩过次数 | **1** |
| 标签 | 网络、排查、校园网 |
| 第一次 | 2026-10-27 |
| 最近一次 | 2026-10-27 |

**症状（当时看到什么）**

```text
ping github.com → 123ms 0% 丢包看着一切正常；curl 同一个 IP → time_connect = 0.000000，TCP 握手根本没完成。
```

**原因（为什么会这样）**

链路在 TCP 端口级丢包，ICMP 不受影响。ping 通只证明网络层可达，不证明应用层能连。换 DNS / 开 DoH / 换 IP 全无效，因为问题不在 DNS。

**解法（怎么解决）**

- 判断依据：curl 的 time_connect=0 就是端口被丢
DoH 救不了，实测三个 DoH 服务器自身都到不了
唯一有效路径：hosts 锁 IP（浏览器侧）+ curloptResolve（git 侧）
注意是间歇性的：16:50 测 20/20 全通，17:12 测 6 个 IP 全挂

## T05 · bat 文件必须 CRLF 换行 + 纯 ASCII（GBK 码页下）

| 项 | 内容 |
|---|---|
| 踩过次数 | **1** |
| 标签 | Windows、bat、编码 |
| 第一次 | 2026-10-27 |
| 最近一次 | 2026-10-27 |

**症状（当时看到什么）**

```text
双击 bat 窗口一闪就关，什么都不执行，也不报错。
```

**原因（为什么会这样）**

Write 工具默认写 LF 换行，cmd.exe 只认 CRLF。另外本机 ACP/OEMCP = 936（GBK），bat 里的 UTF-8 中文会乱码，某些字节组合还会导致解析异常。

**解法（怎么解决）**

- python -c "d=open(f,'rb').read().replace(b'\r\n',b'\n').replace(b'\n',b'\r\n');open(f,'wb').write(d)"
输出全用英文（纯 ASCII）绕开 GBK 问题
结尾加 pause，出错时能看到信息

## T06 · hosts 写入与 DNS 修改需要管理员权限（沙箱也拦）

| 项 | 内容 |
|---|---|
| 踩过次数 | **1** |
| 标签 | Windows、权限、沙箱 |
| 第一次 | 2026-10-27 |
| 最近一次 | 2026-10-27 |

**症状（当时看到什么）**

```text
PowerShell Set-Content 写 hosts 被拒；bash cat >> 被 Windows ACL 拒绝；Set-DnsClientServerAddress 报 CIM 权限错误。
```

**原因（为什么会这样）**

hosts 文件和 DNS 设置都受 Windows 保护。本机 WorkBuddy 会话是非管理员。注意 whoami /groups 里 Administrators 显示「只用于 拒绝的组」是 UAC 正常表现，不代表不是管理员。

**解法（怎么解决）**

- 既定原则：需要管理员的操作直接交给用户在提权终端跑
写成 bat 自动提权：net session 检测 + Start-Process -Verb RunAs
git 全局配置不需要管理员，沙箱里可直接改

## T07 · git ls-files 对中文路径做八进制转义，统计文件数必须加 -z

| 项 | 内容 |
|---|---|
| 踩过次数 | **1** |
| 标签 | git、统计、编码、盘点 |
| 第一次 | 2026-10-27 |
| 最近一次 | 2026-10-27 |

**症状（当时看到什么）**

```text
统计根目录 .py 数量时 git ls-files | grep -c "\.py$" 返回 0；用 git ls-tree 看到文件名显示成 "\351\273\210..." 一串八进制
```

**原因（为什么会这样）**

git 默认 core.quotepath=true，输出非 ASCII 路径时用 C 风格转义而不是原样输出；配合 wc -l / grep 统计时路径被拆错

**解法（怎么解决）**

- 统计文件数统一用 git ls-files -z | tr "\0" "\n"；查看文件名用 git -c core.quotepath=false ls-tree --name-only HEAD

## T08 · bash for 循环里 $(...) 会被空格拆词，含空格的文件名统计会漏

| 项 | 内容 |
|---|---|
| 踩过次数 | **1** |
| 标签 | bash、统计、文件名 |
| 第一次 | 2026-10-27 |
| 最近一次 | 2026-10-27 |

**症状（当时看到什么）**

```text
for f in $(git ls-files ...); do wc -l < "$f"; done 统计出 22 个文件，真实是 23 个；stderr 报 "默认参数: No such file or directory"、"& 关键字参数.py: No such file"
```

**原因（为什么会这样）**

命令替换的结果会做词分割（word splitting）和 glob 展开，含空格的路径被拆成多个参数，循环里当成不存在的文件名

**解法（怎么解决）**

- 改用 while read -d "" 逐行读，或直接交给 Python 处理：git ls-files -z | python -c "import sys; ..."

## T09 · 预览本地 xlsx 后原文件从磁盘消失，只剩备份在

| 项 | 内容 |
|---|---|
| 踩过次数 | **1** |
| 标签 | WorkBuddy、文件安全、备份、xlsx |
| 第一次 | 2026-10-27 |
| 最近一次 | 2026-10-27 |

**症状（当时看到什么）**

```text
调用 present_files 预览桌面技能清单 xlsx 后，桌面上的 AI应用工程师技能清单.xlsx 整份不见了（ls 看不到，全盘 find 也搜不到）；只留 18:22 做的备份。全盘搜到 .workbuddy/workspace/sessions/<id>/modify_backup/ 但里面只有「更新前」的版本
```

**原因（为什么会这样）**

**解法（怎么解决）**

- ① 重要文件改前必备份，且改动要脚本化（脚本已提交 git 就能 100% 重跑复现）；② 桌面留工作副本 + D 盘留权威副本 + git 留快照，三层保险；③ 谨慎 present 本地 xlsx，改用文字汇报表格内容

## T10 · 执行即写入的脚本不能拿来"测试"——我为了验证路径改对没，把错题池污染了

| 项 | 内容 |
|---|---|
| 踩过次数 | **1** |
| 标签 | Python、脚本、git、测试 |
| 第一次 | 2026-10-27 |
| 最近一次 | 2026-10-27 |

**症状（当时看到什么）**

```text
只是想确认 _登记新错题.py 改完路径还能跑，直接执行了，结果它当场新增 E21/E22/E23 三条错题（JSON 里多了 3 条，md 被自动重新渲染）
```

**原因（为什么会这样）**

这类脚本是"执行即写入"型，副作用和数据变更不可逆，且没有 dry-run 开关；测试它 = 真的做了一遍

**解法（怎么解决）**

- ① 测试写数据的脚本前先 git stash / 先备份，或在副本上测；② git checkout -- <数据文件> 回滚 JSON，再 render 一次让 md 同步回来；③ 给这类脚本加 --dry-run 参数
