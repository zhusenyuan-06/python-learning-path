## 第 1 题（E01）· if 缺 else/return

**实跑现象：**
```
已存在，未覆盖
结果: {'小明': {'电话': '999'}}  → 覆盖了
```

**① 错在哪：**
`contacts[姓名] = {"电话": 电话}` 这一行在 `if` **外面**。
`if` 命中时只打印了一句话，**没有任何东西阻止它继续往下执行**。

**② 改写（两种都行）：**

方案 A —— 加 `else`：
```python
def 加联系人(contacts, 姓名, 电话):
    if 姓名 in contacts:
        print("已存在，未覆盖")
    else:
        contacts[姓名] = {"电话": 电话}
```

方案 B —— 加 `return`（更常用）：
```python
def 加联系人(contacts, 姓名, 电话):
    if 姓名 in contacts:
        print("已存在，未覆盖")
        return
    contacts[姓名] = {"电话": 电话}
```

**③ 原来为什么没报错？改完凭什么就对了？**

> 原来为什么没报错？因为 `print("已存在，未覆盖")` 是**完全合法的语句**。
> Python 的规则里，**没有任何一条说「你打印了却没阻止后面的覆盖」是错误** ——
> `print` 只是显示一句话，它对程序状态**没有任何约束力**。
>
> 改完凭什么就不覆盖了？因为 `return` 让函数**当场结束**，
> 下面的 `contacts[姓名] = ...` 根本不会被执行。

> 📌 **这题值得贴在显示器上：**
> **「打印成功」≠「数据没被改」。**
> 屏幕话和真实状态，是两回事。

## 第 2 题（E02）· 同一个变量名承担两种角色

**实跑现象：**
```
TypeError : 'int' object is not iterable
```

**① 错在哪：**
```python
def 求和_错版(nums):
    nums = 0           # ← 这里把形参 nums 覆盖成了整数 0
    for i in nums:     # ← for 一个 0 → TypeError
```
**`nums` 一个名字干了两件事**：既是「传进来的列表」，又是「累加器」。
第 2 行执行完，`nums` 从「列表」变成了「数字 0」，**原参数被彻底覆盖**。

**② 改写：**
```python
def 求和(nums):
    total = 0          # ← 累加器另起一个名字
    for i in nums:     # ← nums 还是原来那个列表
        total += i
    return total
```

**③ 为什么「入参被覆盖」比「结果算错」更危险？**

> 因为**调用方不会发现**。
>
> 错误的结果，调用方一眼能看出来（数字不对，他知道要去查）。
> 但入参被覆盖是**副作用** —— 调用方手里的列表已经不是他传进去的那个了，
> 而他**毫不知情**。
>
> 更狠的是：这次恰好报了 `TypeError`，所以你**当场发现了**。
> 如果第 2 行写成 `nums = list(nums)`（这行不报错），
> 那就是**纯静默** —— 函数返回正常，调用方拿着被换掉的列表继续用，
> 错误会漂到很远的地方才爆出来。
>
> **入参被改 = 你在别人不知道的情况下动了别人的东西。**

> 📌 **规矩：一个变量只干一件事。**
> 形参是「输入」，累加器是「过程中的状态」，两者必须分开命名。

## 第 3 题（E03 + E13）· 漏 .strip() + 方法结果没赋值回去

**实跑现象：**
```
输入: '苹果，  香蕉。 苹果'
结果: {'苹果，': 1, '香蕉。': 1, '苹果': 1}
```
注意 `'苹果，'` 和 `'苹果'` 被算成了**两个不同的词**。

**① 两个问题分别在哪：**

**E03（漏 strip）在这一行：**
```python
w = w.lower()                       # ← 只 lower，没 strip
```
`lower()` 只把大写变小写，**不会去掉标点**。`'苹果，'.lower()` 还是 `'苹果，'`。

**E13（没赋值回去）—— 这题要仔细看：**
```python
w = w.lower()
```
这一行**有赋值**，所以严格说 E13 在这一处**没犯**。
但**它离犯 E13 只有一步** —— 如果写成：
```python
w.lower()          # ❌ 白干，w 没变
```
就是标准的 E13（`lower()` 返回**新字符串**，不原地修改）。

> ⚠️ **这道题我故意放得有点绕**，因为它考的是**你能不能自己看出「没犯 E13」也是答案的一部分**。
> 上一轮 10-28 变式题里，你就是在这里栽的：
> 「把 `p = p + [3]` 当成 `+=`，以为别名会跟着变（实际不会）」。

**② 改写（清洗链要完整）：**
```python
停用词 = {"的", "了", "是", "我", "你", "在"}

def 统计词频(文本):
    words = 文本.split()
    counts = {}
    for w in words:
        w = w.lower().strip(".,!?，。！？")   # ① lower + strip，中英文标点都去
        if w in 停用词: continue              # ② 停用词跳过
        if not w: continue                    # ③ strip 后可能变空串（E19）
        counts[w] = counts.get(w, 0) + 1
    return counts
```
实跑：
```
输入: '苹果，  香蕉。 苹果'
结果: {'苹果': 2, '香蕉': 1}     ← 对了
```

**③ 停用词那行为什么不能省？**

> 因为中文里「的」「了」「是」「我」「在」这些词的**出现频率极高**。
> 不跳过它们的话，排行榜第一名永远是「的」，第二名永远是「了」——
> **排出来的不是关键词，是虚词。**
>
> 更本质地说：停用词是**没有信息量**的词。
> 词频统计要的是「这个文本里哪些词承载了信息」，
> 而虚词承载不了信息 —— 统计它们只会淹没真正有意义的词。

> 📌 **清洗链的固定顺序（背下来）：**
> **`.lower()` → `.strip(".,!?，。！？")` → 判空 → 停用词过滤**
> 每一步都在解决一个具体的坑：E13 / E03 / E19 / 词频污染。

## 第 4 题（E04）· sorted 漏了 reverse=True

**实跑现象：**
```
输入: {'a': 5, 'b': 1, 'c': 9}
结果: [('b', 1), ('a', 5), ('c', 9)]     ← 升序！
```

**① 错在哪：**
```python
after = sorted(counts.items(), key=lambda x: x[1])   # ← 少了 reverse=True
```
`sorted` **默认升序**。要「最高的排最前面」必须显式写 `reverse=True`。

**② 改写：**
```python
def 取前5(counts):
    after = sorted(counts.items(), key=lambda x: x[1], reverse=True)
    return after[:5]
```
实跑：
```
[('c', 9), ('a', 5), ('b', 1)]     ← 对了
```

**③ 原来为什么没报错？**

> 因为 `sorted` 加不加 `reverse=True` **都是完全合法的调用**。
> 它不会报错，不会警告，它只是**安静地给了你反过来的顺序**。
>
> 这就是「静默错误」的典型：**没有异常，但结果是错的。**
> 你只能靠「拿预期输出对照」才能发现。

> 📌 **写排序前先问一句：「升序还是降序？」**
> 写完再拿一行已知数据**跑一遍看输出**。10-28 那天你就是因为
> 「以为 `[:3]` 会切掉并列第 3 名」栽的 —— 跑一遍就知道。

> 💡 **另外一个坑（10-28 一起栽的）：**
> `sorted(字典)` 是按 **key** 排的，你要按 **value** 排，
> 所以必须先 `.items()`。写 `sorted(counts, ...)` 会报
> `TypeError: '<' not supported between instances of 'str' and 'int'`
> —— 这个反而是好事，**它当场炸给你看**。

## 第 5 题（E25）· not in 和 not 混淆

**实跑现象：**
```
输入: '不存在的文件.txt'（文件确实不存在）
结果: 文件在      ← 判断永远成立
```

**① 错在哪：**
```python
if os.path.exists(路径) not in []:
```
`os.path.exists(...)` 返回的是 **`True`/`False`（一个布尔值）**，
不是容器。拿布尔值去 `not in` 一个列表，语义上说不通。

**② 改写：**
```python
def 检查文件(路径):
    if os.path.exists(路径):
        return "文件在"
    return "文件不在"
```
或者用 `not`：
```python
    if not os.path.exists(路径):
        return "文件不在"
```

**③ not in 和 not 的右边分别要求是什么？**

| | 右边要求 | 例子 |
|---|---|---|
| `not in` | 必须是**容器**（list/dict/set/tuple/str） | `"a" not in "abc"` ✅ |
| `not` | 必须是**单个布尔值** | `not True` ✅ |

> **`not in` 右边要能「装东西」，`not` 右边只能是一个开关。**

> 📌 **为什么这题是静默错误？**
> `True not in []` 在语法上**完全合法**，而且**永远为 True**
> （布尔值不可能出现在空列表里）。
> 所以你的 `if` 永远进，文件永远报「在」。
> **没有任何报错提示你**。

## 第 6 题（E24）· open('w') 先清空

**实跑现象（0 字节现场重现）：**
```
崩了: TypeError Object of type set is not JSON serializable
19 bytes -> 0 bytes → 0字节!旧数据没了
```

**① 错在哪（关键：错的是【顺序】，不是【模式】）：**
```python
with open(DATA_FILE, "w", encoding="utf-8") as f:
    f.write(json.dumps(tasks, ensure_ascii=False))
```
`json.dumps(...)` 在 `with` **里面** —— 也就是**开门之后**才计算。
崩了 → 文件已经被清空 → 0 字节。

**模式 `'w'` 本身没错**，这段代码本意就是写。
错的是**清空发生在「内容准备好」之前**。

**② 改写（写法 C · 原子替换）：**
```python
import os

def 保存任务(tasks, path="todos.json"):
    tmp = path + ".tmp"
    try:
        with open(tmp, "w", encoding="utf-8") as f:
            f.write(json.dumps(tasks, ensure_ascii=False))
        os.replace(tmp, path)
    except Exception:
        if os.path.exists(tmp):
            os.remove(tmp)
        raise
```
实跑：`19 bytes -> 19 bytes`，旧数据完好。✅

**③ 为什么不能把 `'w'` 改成 `'r'`？改了对会报什么错？**

改成 `'r'` 之后，`f.write(...)` 会立刻报：
```
io.UnsupportedOperation: not writable
```

因为 `'r'` = 只读，文件对象**没有写权限**。

> 📌 **这正是你 10-29 答错的地方。**
> 你的推理是「用了 w → w 会清空 → 该改成 r」。
> 但这段代码**本来就是要把 tasks 存进去**，
> 下一行就是 `f.write(...)` —— 它当然要用写模式。
>
> **你把「模式选错」和「时机错了」搞混了：**
>
> | | 是什么 | 层面 |
> |---|---|---|
> | **模式选错** | 这段代码要读，你写了 `'w'` | 逻辑意图 |
> | **时机错了** | 这段代码要写，但内容没备好，文件已被清空 | 执行顺序 |
>
> E24 考的是**后者**。正解是**改顺序**或**原子替换**，不是改模式。

## 第 7 题（E27）· 复制粘贴的代码块

**实跑现象：** `with open` 在 `保存任务_抄写版` 里出现 **3 次**。

**① 重复在第 220、225、230 行**（原稿行号）。
三份代码除了缩进和 print 文案，**完全一样**。

> 💡 **怎么自己找到？** `grep -n "with open" 练习/10.30练习_改bug.py`
> —— 第 220/225/230 行是那三份重复的（189 和 315 行是别的题，不是本题）。

**② 改写：**
```python
def 保存任务(tasks, path=DATA_FILE):
    with open(path, "w", encoding="utf-8") as f:
        f.write(json.dumps(tasks, ensure_ascii=False))


def 处理命令(tasks, cmd, text=""):
    if cmd == "quit":
        保存任务(tasks)
        print("再见！")
    elif cmd.startswith("add "):
        tasks.append({"text": text, "done": False})
        保存任务(tasks)
        print("已添加")
    elif cmd.startswith("done "):
        tasks[0]["done"] = True
        保存任务(tasks)
        print("已完成")
    return tasks
```
改完后 `with open` **只剩 1 处**（在 `保存任务` 里）。

**③ 判断标准：**

> **同一个 `with open(...)` 在一个文件里出现第二次，就该抽成函数。**
>
> 更好记的版本（你 10-29 学的）：**「改动有没有清单」**。
> 如果这次改动**没有一张「哪几处要改」的清单**，
> 说明你在靠眼睛找 —— 而复制粘贴的代码**靠眼睛找必错**。
>
> 实操做法：改之前先写三行清单，然后逐条打勾。
> ```
> 这次要改的：写文件的逻辑
> 要改的地方：① 保存任务函数 ② 三个分支 ③ 讲义示例
> ```

> 📌 **10-29 的真实现场：**
> 你在 `quit` 分支和 `add` 分支之间删错了行，
> 把 `add` 分支的 `add_task(tasks, text)` 误删了 —— 结果任务加不进去。
> **根因就是这两段长得太像。**

## 第 8 题（E28）· 缩进栈层级不匹配

**实跑现象：**
```
✅ IndentationError: unexpected indent (<test>, line 5)
```

**① 错在哪：**
```python
if cmd.startswith("add "):
    text = cmd[4:]
        """              ← 这一层缩进【栈里没有】
        这里多缩进了一层
        """              ← 回到 12 格
    add_task(tasks, text)
```
Python 建立缩进栈时遇到一个「没进过也没退过」的层级，下一行回到一个栈里不存在的缩进 → 直接报 `IndentationError`。

**注意：不是「多了几格」** —— 12 格 / 16 格都行，
**层级不对才是问题**。

**② 改写：**
```python
def 处理命令(cmd, tasks):
    if cmd.startswith("add "):
        text = cmd[4:]
        add_task(tasks, text)
```
**docstring 整段删掉了。**

> 📌 **为什么该删？**
> docstring（`"""..."""`）是**函数的说明书**，应该写在 `def` 下面。
> 写在 `if` 分支里，它只是一个**没人用的字符串字面量** ——
> 白占地方，还制造层级噪音。
>
> 顺带说：**删掉它之后，报错就消失了** ——
> 这就是「治本」和「治标」的区别（你 10-29 答的是「改为 12 格」，那是治标）。

**③ 为什么缩进是「层级栈」而不是「排版对齐」？**

> 因为 Python 用缩进表达的是**语法结构的嵌套关系**，不是「看起来整齐」。
>
> 栈的意思是：只能**进一层**或**退一层**，不能跳。
> ```
> if cmd.startswith('add '):     ← 层级 1
>     if len(cmd) > 4:           ← 层级 2
>         """                    ← 层级 3
>         这里缩进 16 格了          ← 层级 4 ← 栈里突然多了一层 ❌
>         """                    ← 层级 3  ← 回到 12？栈里有 12
>     add_task(tasks, text)       ← 层级 2
> ```
>
> **所以规则是：同一层必须缩进完全一样**（4 格就 4 格，8 格就 8 格），
> 而且必须对应一个**真实的语法层级**。

## 第 9 题（E26 + E01）· 先存盘后改内存

**实跑现象：**
```
内存里有 1 条；磁盘上: []
```
内存里任务已经加上了，**但磁盘上还是空列表** —— 存的是旧值。

**① 错在哪（哪两行顺序反了）：**
```python
save_tasks(tasks)                              # ← 先存盘
tasks.append({"text": text, "done": False})    # ← 后改内存
```
`save_tasks` 存的是**调用那一刻** `tasks` 的内容。
先存后改 = 存进去的是**改动前的旧值** —— 等于白存。

**② 改写：**
```python
def 加任务并保存(tasks, text):
    tasks.append({"text": text, "done": False})   # ① 先改内存
    save_tasks(tasks)                              # ② 再写磁盘
    return tasks
```
实跑：磁盘上 `[{"text": "买菜", "done": false}]` ✅

**③ 为什么「存了旧值」不报错？**

> 因为「存了旧值」**不违反任何语法规则**。
> `save_tasks(tasks)` 这个调用完全合法，
> 程序也完全正确地执行了「把当前 tasks 写进文件」——
> 它只是不知道**你**想存的是**新值**。
>
> **程序没有「意图」的概念，它只知道「你让我存什么我存什么」。**

> 📌 **一句话记住：改完再存。**
> 这四个字直接抄进 `todo-cli/README.md` 的坑 2 里。
