## 第 1 题（E15）· 静默错误三件套

### ①②③ 各错在哪

| | 错 | 后果 |
|---|---|---|
| ① | `w = w.lower()` 少了 `.strip()` | `"hello,"` 和 `"hello"` 变成两个不同的词，词频被标点污染 |
| ② | `sorted(...)` 少了 `reverse=True` | 次数**最少**的排第一，排名整个是倒的 |
| ③ | `if` 打印完提示后**没有 return** | 照样往下走，把老数据覆盖了 |

### 改写后

```python
w = w.lower().strip(".,!?")
after = sorted(counts.items(), key=lambda x: x[1], reverse=True)
if 姓名 in contacts:
    return "未覆盖"
contacts[姓名] = {"电话": 电话}
```

### 为什么 ③ 是「静默」的

因为 `print("未覆盖")` **不是控制语句**。它只是打印一句话，打印完程序继续往下执行。
Python 看到 `if` 块结束就以为这段结束了，照样执行下一行 `contacts[姓名] = ...`。
所以你屏幕上明明写着"未覆盖"，数据却已经被覆盖了 —— **屏幕上看到什么，和内存里是什么，是两件事**。

**这就是"静默错误"最阴的地方**：报错型错误（TypeError）Python 会拦你，你立刻知道；静默错误没人拦，它默默把你的数据搞坏，你以为跑通了就是搞定了。

### 实测（真跑）

```
words = ["hello,", "hello", "world!"]

❌ 不 strip  -> {'hello,': 1, 'hello': 1, 'world!': 1}     ← 三个词
✅ strip 后  -> {'hello': 2, 'world': 1}                    ← 两个词，hello 才是 2
```

同一个 `"hello"` 被算成 1 次而不是 2 次 —— 统计结果直接错一半。

## 第 2 题（E02）· 一个变量名只干一件事

### 有几处变量名被复用

**3 处。**

| # | 变量 | 前一个角色 | 后一个角色 | 冲突后果 |
|---|---|---|---|---|
| 1 | `nums` | 参数：待求和的列表 | 累加器：整数 | `for i in nums` 时 nums 已是 int → **TypeError** |
| 2 | `counts` | 字典：词 → 次数 | 整数：某一次的次数 | 字典被覆盖成 int，之后再用字典就炸 |
| 3 | `w` / `counts`（循环变量） | 循环里的临时值 | 循环外还在用 | 出了循环类型已变，误用时静默出错 |

### 改写后

```python
def sum_list(nums):
    total = 0
    for i in nums:
        total += i
    return total

for w, c in t.items():
    print(w, c)
```

**规矩**：字典叫 `counts`，次数叫 `c`；入参叫 `nums`，累加器叫 `total`。**一个名字从头到尾只干一件事。**

### 报错信息（实测）

```
❌ TypeError: 'int' object is not iterable
✅ sum_list([1,2,3]) -> 6
```

另外 `for w, counts in t:` 本身也错 —— 遍历字典默认只拿到 key，要拿键值对必须写 `.items()`：

```
❌ ValueError: too many values to unpack (expected 2)
✅ for w, counts in t.items():  →  python 5 / data 2
```

### 循环变量泄漏

```python
for w, c in pairs:
    pass
print(w, c)      # w='data' c=2 —— 出了循环还在，类型已经被换掉了
```

Python 的循环变量**不自动回收**。循环结束后 `w`、`c` 还在作用域里，很容易被后面的代码误用。
**规矩**：循环变量用完就别再碰；要留就用新名字接住。

## 第 3 题（E01）· if 缺 else / return

### 1. 调用后 contacts["小明"] 变成什么

```python
contacts = {"小明": {"电话": "13800138000"}}
a("小明", "13911112222")
```

**实测结果**：

```
调用前: {'小明': {'电话': '13800138000'}}
已存在，未覆盖          ← 屏幕上确实打印了
调用后: {'小明': {'电话': '13911112222'}}   ← 但数据已经被覆盖了！
```

### 2. 改写

```python
def a(name, p):
    if name in contacts:
        return "已存在，未覆盖"      # return 直接结束函数
    contacts[name] = {"电话": p}
    return "已添加"
```

**关键**：光 `print` 不够，必须 `return`（或者用 `else:` 块把主逻辑包起来）。`return` 才是真正的"停在这"。

### 3. if/elif/else 链里的对应坑

叫**「缺 else 分支」**。危害一样：所有条件都不命中时，变量从没有被赋值，后面用到它就炸。

实测：

```
完整链（有 else）-> 中
缺 else，x=1 -> NameError: name 'r' is not defined
```

**注意**：缺 else 不一定马上报错——如果变量在上一次循环里被赋过值，它就是**上一轮的旧值**，那就是静默错误了。
所以 `if/elif` 链要么配 `else`，要么在链前面先给个默认值。

## 第 4 题（E04）· sorted 漏 reverse=True

### 1. print(after[0]) 会输出什么

**实测**：

```python
counts = {"python": 5, "data": 2, "learn": 3, "code": 2}
after = sorted(counts.items(), key=lambda x: x[1])
print(after[0])
```

```
❌ ('data', 2)     ← 次数最少的排在了第一
```

### 2. 正确写法

```python
after = sorted(counts.items(), key=lambda x: x[1], reverse=True)
print(after[0])    # ('python', 5)
```

**注意**：代码里**不会报任何错**，它就是安安静静地给你一个反的排名。这就是静默错误。
`reverse=True` 的意思是"按 key 值**降序**排"。

### 3. counts 为空 {} 会怎样

```
sorted({}, ...) -> []            ← 不报错
after[0]        -> IndexError: list index out of range
```

**排序不报错，取第一个才报错**。所以取 `after[0]` 之前，最好先判断 `if not after:`。

## 第 5 题（E05）· 类型统一

### 1. 隐患在哪个操作上会炸

```python
contacts = {"小明": {"电话": 13800138000}, "小红": {"电话": "13900139000"}}
```

**实测**：

```
类型: ['int', 'str']      ← 同一个字段，两种类型
```

隐患在这几个操作上：
- `len(contacts["小明"]["电话"])` → **TypeError: object of type 'int' has no len()**
- `"电话" + contacts["小红"]["电话"]` → 数字那边会 TypeError
- `max(len(v["电话"]) for v in contacts.values())` → 直接崩

实测验证：

```
✅ 统一成字符串后 -> 数字位数: 11     ← 两个都能算
```

### 2. 改写

```python
contacts = {
    "小明": {"电话": "13800138000"},
    "小红": {"电话": "13900139000"},
}
```

### 3. 为什么统一成字符串更好

三个理由，**都实测过**：

1. **前导 0 会丢**。手机号/学号可能有前导 0：
   ```
   "013800138000" -> len 12     ← 字符串，前导0还在
   int(...)       -> 13800138000 ← 前导0没了
   ```
2. **JSON 里要一致**。数字不带引号、字符串带引号：
   ```
   {"电话": 13800138000}    ← 数字
   {"电话": "13800138000"}  ← 字符串
   ```
   同一个字段两种类型，读的时候要判断，序列化出去也对不齐。
3. **号码不该做运算**。电话号码相加（`int + 1` → 13800138001）没有业务意义，但代码里技术上能跑 —— 这正是静默错误的土壤。

**判断标准**：**做标识用（ID、手机号、邮编、身份证）→ 一律字符串；做数量用（价格、数量、分数）→ 一律数字。**

## 第 6 题（E03）· 漏 .strip()

### 1. counts 长什么样

**实测**：

```python
words = ["hello,", "hello", "world!"]
```

```
❌ 不 strip -> {'hello,': 1, 'hello': 1, 'world!': 1}
```

`"hello,"` 和 `"hello"` 变成了**两个不同的词**。

### 2. 改写

```python
for w in words:
    w = w.lower().strip(".,!?")
    if w:                              # 防止空词进统计
        counts[w] = counts.get(w, 0) + 1
```

实测：

```
✅ strip+空词过滤 -> {'hello': 2, 'world': 1}
```

### 3. strip() 的语义

**`.strip()` 只去两端，不去中间。** 实测：

```
"  Python  ".strip()              -> 'Python'      ← 默认去所有空白
"，你好。世界！".strip("，。！？") -> '你好。世界'   ← 去两端的中文标点
"abc.,!?".strip(".,!?")          -> 'abc'
```

要点：
- `strip()` **不带参数** → 只去空白字符（空格、换行、tab）
- `strip(".,!?")` → 去**你指定**的这些字符（不是"标点"，是"这几个字符"）
- **只去两端**：中间的标点它不管。所以 `"a,b,c".strip(",")` → `'a,b,c'`（两端本来就没逗号）
- 想要"每个词都干净"，得靠**切分**（`split`）而不是 `strip`

## 附加（E16）· x[1] 取到什么，取决于 x 是什么类型

### 1. 会报错吗

**不会报错。** 实测：

```python
counts = {"data": 2, "learn": 3, "code": 2, "python": 5}
r = sorted(counts.keys(), key=lambda x: x[1])
```

```
❌ 不报错 -> ['data', 'learn', 'code', 'python']
```

### 2. r 会是什么、按什么排

```
[('data', 'a'), ('learn', 'e'), ('code', 'o'), ('python', 'y')]
```

**它按每个词的第 2 个字母排**：a → e → o → y。

因为 `x` 是 `counts.keys()` 里的一个元素，是个**字符串**，`x[1]` 取的是**第 2 个字母**。
字符串第 2 个字母可以比较大小，所以能排 —— 所以它**不报错**，只是排的根本不是你想要的"次数"。

### 3. 上周你答"keys() 不能用 x[1]"

**这个答案上次记为 fail，现在仍然是不准确的。** 更准确的说法是：

> `keys()` 里的 `x` 是字符串，`x[1]` 是第 2 个字母 —— **能排，但排的是字母不是次数**。
> 想按次数排，必须让 `x` 是**键值对**，用 `.items()`。

```python
✅ sorted(counts.items(), key=lambda x: x[1], reverse=True)
   -> [('python', 5), ('learn', 3), ('data', 2), ('code', 2)]
```

**这题为什么重要**：它是你**第一次亲手撞上静默错误**。类型对了、能跑、无报错，但结果是错的。
Python 的 `sorted` 不会帮你检查 `x[1]` 取到的是不是你想要的东西 —— **它只管排，不管你排的是什么。**

# 🧠 概念快查 · 答案与讲解

> 全部是实测输出。写答案卷时脚本跑出来的原话。

## A. dict 的三种遍历

```python
d = {"a": 1, "b": 2}
```

```
d.keys()   -> ['a', 'b']    类型: list
d.values() -> [1, 2]
d.items()  -> [('a', 1), ('b', 2)]
list(d)     -> ['a', 'b']    ← 等价于 list(d.keys())
```

**`items()` 最重要** —— 它一次给你 key 和 value，不用再回 dict 里查一次。

## B. set 的四个运算符

```python
A = {1, 2, 3}
B = {3, 4, 5}
```

```
A | B  (并集)   -> {1, 2, 3, 4, 5}   == A.union(B)
A & B  (交集)   -> {3}               == A.intersection(B)
A - B  (差集)   -> {1, 2}            == A.difference(B)
A ^ B  (对称差) -> {1, 2, 4, 5}      （在A或B但不在两边）
```

**坑**：`|` `&` `-` `^` **只对 set 有效**：

```
[1, 2] | [3]  →  TypeError: unsupported operand type(s) for |: 'list' and 'list'
```

list 想用这些运算，必须先 `set()`。

## C. 嵌套 dict 的三种查法

```python
stu = {"小明": {"语文": 90, "数学": 85}}
```

```
1) stu["小明"]["语文"]              -> 90
2) stu.get("小刚", {}).get("语文")   -> '无此人'     ✅ 安全
3) stu.get("小刚").get("语文")       -> ❗AttributeError: 'NoneType' object has no attribute 'get'
```

**关键**：`.get("小刚")` 拿到的是 `None`（不是 dict），再往上链式 `.get()` 就炸。
**规矩：嵌套查几层，每层都要给默认值 `{}`。**

## D. 三种推导式的类型

```python
counts = {"a": 3, "b": 1, "c": 3}
```

```
{w for w, c in counts.items() if c == 1}     -> {'b'}          集合推导式 → set
{w: c for w, c in counts.items() if c == 1}   -> {'b': 1}       字典推导式 → dict
[w for w, c in counts.items() if c == 1}      -> ['b']          列表推导式 → list
```

**看冒号**：大括号里**有冒号 = dict，没冒号 = set**；方括号 = list。

## E. 三个字符串方法

```
s = "  Hello, World!  "

s.strip()   -> 'Hello, World!'      ← 只去两端空白
s.lower()   -> '  hello, world!  '  ← 转小写
s.split()   -> ['Hello,', 'World!'] ← 按空白切分成 list
s.strip('!')-> '  Hello, World!  '  ← 去两端【指定的字符】
```

**`strip()` 只去两端，不去中间**。`"a,b,c".strip(",")` → `'a,b,c'`（两端本来就没逗号）。
想去中间的标点，得靠 `split()` 或 `translate()`。

## F. 字符串 vs 列表

```
❌ s[0] = "x"   → TypeError: 'str' object does not support item assignment
✅ lst[0] = "x" → ['x', 'b']
```

**字符串不可变**（immutable）。字符串的"改"= 生成一个新字符串，再赋值回去。
列表可变（mutable），能原地改。

## G. sorted vs sort

```python
lst = [3, 1, 2]
sorted(lst) -> [1, 2, 3]   | lst 本身 -> [3, 1, 2]   ← 返回新 list，原 list 不变
lst.sort()  -> 返回 None     | lst2 本身 -> [1, 2, 3]  ← 原地排序，返回 None
```

**记忆点**：`sorted()` 有 `s` 开头（sorted = 排好序的），不改变原东西；`sort()` 原地排、返回 None。
所以 **`x = lst.sort()` 是错的** —— 把 None 赋给了 x。
