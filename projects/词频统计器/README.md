# 词频统计器 CLI

统计一个文本文件里每个词出现了多少次，**中英文混排都能切**。

这个作品的代码只用了 20 行左右，但它是 RAG 检索、文本清洗、关键词提取的**最小内核** —— 我作品①「课程问答 RAG 机器人」里，文档切分之后统计关键词、给检索结果排序，用的就是这套技术。

**出身**：最早是 `练习/词频统计器进阶版.py`（一个 40 行的教学骨架）。2026-10-28 我在根 README 里把它「诚实降级」成了练习片段，理由是：路径写死在源码里、只支持英文、没有 README 拿不出手。**2026-11-10 改造回作品。**

---

## 功能

- [x] **中英文混排切词**：正则一次搞定，不用先判断文本是中文还是英文
- [x] **词频统计**：每个词出现多少次
- [x] **Top N 排行**：`--top N` 自由指定，默认 10
- [x] **结果可复现**：同一个文件跑两次，输出**逐字完全一样**（次数相同时按词的字典序排，不看谁先出现）
- [x] **可视化输出**：排名 / 次数 / 占比 / 条形图，一眼看出高频词
- [x] **友好报错**：文件不存在 → 中文提示 + 列出当前目录的 txt 文件 + 退出码 1（不是甩一屏红字）
- [x] **`--help`**：自解释用法

## 技术点

### 1. 用正则一次切出中英文词

```python
词模式 = re.compile(r'[\u4e00-\u9fa5]+|[a-zA-Z]+')
```

- `[\u4e00-\u9fa5]+` → 连续的中文汉字（`\u4e00` 是「一」的 Unicode 码位，`\u9fa5` 是「龥」的码位，中文字符集中在这个连续区间；`+` 表示「1 次或多次」）
- `[a-zA-Z]+` → 连续的英文字母
- `|` → 或者，两种都匹配

**为什么不用 `split()`**：它只按**空白**切，中文没有空格 → 整句话变成 1 个词。详见下面的坑 1。

### 2. 词频计数的标准写法

```python
计数[词] = 计数.get(词, 0) + 1
```

`.get(词, 0)` 里那个 `0` 是**默认值**，只在**键不存在**时生效；键存在但值是 `None` 时会返回 `None`（这是个真实的坑，我在工具链坑库里栽过一次）。

### 3. 排序：key 返回元组，保证可复现

```python
sorted(计数.items(), key=lambda x: (-x[1], x[0]))[:N]
```

- `-x[1]` → 次数**取负** → 升序排序时，次数多的反而排前面 = 次数降序
- `x[0]` → 次数一样时按**词的字典序** → 跟词在文件里出现的先后**彻底无关**
- **注意**：用了元组 key 就**不能再写 `reverse=True`**，否则 `reverse` 会把整个元组反转 → 次数变升序

### 4. 正则天然不会有空串

正则里的 `+` 要求**至少匹配 1 个字符**，所以 `findall` **永远切不出空字符串**。这比老练习里「`split()` + `strip()`」的方案安全 —— 那个方案会切出空串，空串还会被当成一个词计数（这是我的错题 E19）。

代码里仍然保留了 `if w` 这一层过滤，理由见下面的坑 4。

### 5. argparse：位置参数 + 可选参数

```python
解析器.add_argument("文件", help="要统计的文本文件路径")        # 位置参数：必填
解析器.add_argument("--top", type=int, default=10, help="...")   # 可选参数：带默认值
```

`type=int` 让 `--top abc` 直接被 argparse 拦下报错，而不是传进来变成字符串。

## 我踩过的坑（这里最值钱）

### 坑 1：`split()` 对中文**完全失效** —— 整句话变成 1 个词

老练习里用的是 `text.split()`。它在英文里没问题，但中文没有空格：

```text
"苹果香蕉苹果。橘子，香蕉！苹果"

split()          → ['苹果香蕉苹果。橘子，香蕉！苹果']   ← 1 个词！
re.findall(...)  → ['苹果香蕉苹果', '橘子', '香蕉', '苹果']   ← 4 个词 ✅
```

**错在哪**：`split()` 只认空白字符。中文里「苹果香蕉」之间没有空白，整段就变成了一个「词」，词频统计直接失去意义。

**改对之后**：换成正则 `[\u4e00-\u9fa5]+|[a-zA-Z]+`，一次把中英文都切出来。

> 💡 **现在我的习惯**：看到「处理文本」先问一句「**会不会有中文**」。有中文就不能用 `split()`。

---

### 坑 2：给函数套了一层 `def` —— 语法全绿，但函数返回 `None`

写这个作品时我把整个 `统计词频` 函数**又套了一层**同名函数：

```python
# ❌ 错的写法（语法完全合法，不报错）
def 统计词频(词们):
    """docstring"""
    def 统计词频(词们):        # ← 多套了一层
        计数 = {}
        for 词 in 词们:
            计数[词] = 计数.get(词, 0) + 1
        return 计数
    # 外层什么都没返回 → 返回 None
```

**错在哪**：内层函数**定义了但从来没被调用**。外层函数执行完就往下走，**没有 return → 返回 `None`**。

**为什么难查**：这个错**不会在出错的地方报错**。真正崩的是后面那行：

```text
AttributeError: 'NoneType' object has no attribute 'items'
     ↑ 报在「取前N」这一行，但病根在「统计词频」
```

**报错位置和真正原因错位** —— 这种最耗时间。

**改对之后**：把内层的 `def` 删掉，让函数体直接属于外层：

```python
# ✅ 改对之后 —— 这就是 词频统计器.py 里现在 统计词频() 的写法
def 统计词频(词们):
    """docstring"""
    计数 = {}
    for 词 in 词们:
        计数[词] = 计数.get(词, 0) + 1
    return 计数
```

> 💡 **现在我的习惯**：函数体里如果看到 `def` 开头 → **多套了一层**。
> 另外记住一条铁律：**函数末尾必须有 `return`**，哪怕是 `return None`。

### 坑 3：`sorted` 给了 `key` 就**只比 key** —— 次数相同时顺序看「谁先出现」

我一开始写的是：

```python
# ❌ 不够好的写法
return sorted(计数.items(), key=lambda x: x[1], reverse=True)[:N]
```

**错在哪**：这行**能跑、结果也对**（同一个文件跑两次结果一样），但它的排序规则有个隐含前提 —— **次数相同时，保持词在文件里「第一次出现」的顺序**。

**实测**（两个文本词频**完全相同**，只是词出现的先后不同）：

```text
A = "apple banana apple banana orange apple orange"
B = "orange apple banana orange apple banana apple"
两者词频都是：apple:3, banana:2, orange:2

写法① key=lambda x: x[1], reverse=True
  A → [('apple',3), ('banana',2), ('orange',2)]
  B → [('apple',3), ('orange',2), ('banana',2)]     ← banana/orange 顺序反了！

写法② key=lambda x: (-x[1], x[0])
  A → [('apple',3), ('banana',2), ('orange',2)]
  B → [('apple',3), ('banana',2), ('orange',2)]     ← 两边一致 ✅
```

**为什么这样设计**：结果**依赖词在文件里出现的顺序**，对使用者来说是很反直觉的 —— 同样两个词谁排前面，居然取决于它们在原文里的位置。改成元组 key 后，规则变成「**次数降序 + 次数同则按词字典序**」，跟输入顺序彻底无关。

**改对之后**：

```python
# ✅ 改对之后 —— 这就是 词频统计器.py 里现在 取前N() 的写法
return sorted(计数.items(), key=lambda x: (-x[1], x[0]))[:N]
```

> ⚠️ **配套的坑**：用元组 key 就**千万别再写 `reverse=True`**。实测 `key=lambda x: (-x[1], x[0]), reverse=True` 会把次数变成**升序**（最高频的排到最后）—— 因为 `reverse` 反转的是**整个元组**，不只次数。
>
> 💡 **现在我的习惯**：写排序先问一句「**次数一样的时候，谁该在前？**」—— 这个问题不回答，排序就是不确定的。

### 坑 4：多一行不认识的 `import` → **程序根本起不来**

改这个作品时，文件里凭空多了一行：

```python

```

**错在哪**：`sqlalchemy` 是数据库 ORM 库，这个作品**一行数据库代码都没有**，而且本机也没装。

**后果比逻辑错还狠**：程序在 **import 阶段**就炸了 ——

```text

```

**自己的代码一行都没跑到**。如果这是别人的项目，你甚至会怀疑「是不是我电脑环境坏了」。

**改对之后**：删掉那一行。

> 💡 **现在我的习惯**：看到「我不认识这个 import」→ **先删掉再想**。多一行不认识的 import，程序就起不来。

### 坑 5（防御性）：`if w` 留着不删 —— 空串是**假值**

老练习用 `split()` + `strip()` 时，切出过空串：

```text
"apple , . banana ,"
  split          → ['apple', ',', '.', 'banana', ',']
  split+strip    → ['apple', '', '', 'banana', '']     ← 3 个空串！
  计数            → {'apple': 1, '': 3, 'banana': 1}    ← 空串被当成 3 个词！
```

这是我的**错题 E19**（`strip` 后可能变成空串，空串被算进词频）。

**但本作品用的是正则，天然切不出空串**（`+` 要求至少 1 个字符）。那 `if w` 还有必要吗？

**留着**，两个理由：
1. **防御性**：万一以后正则改了、或者有人把切词逻辑换回 `split()`，这一行就是保险
2. **教学价值**：这一行把 E19 的教训**固化在作品代码里**了 —— 读代码的人能直接看到「作者知道空串这个坑，并留了防护」

**关键知识点**：空串是**假值**。

```python
bool("")     → False    ← 空串是假值
bool(" ")    → True     ← ⚠️ 但一个空格是真值（不过 split() 不会留下纯空格词，这里安全）
bool("0")    → True     ← ⚠️ 字符串 "0" 也是真值（只有数字 0 才是假值）
```

## 已知限制

### ⚠️ ① 不区分大小写

`Python` / `python` / `PYTHON` 算**3 个不同的词**。

实测示例文本里：`python` 出现 6 次、`Python` 1 次、`PYTHON` 1 次，分成三条统计。

**为什么不做 `--ignore-case` 选项**：加一个开关就多一条「参数组合 × 结果」的验证分支，而这个作品的定位是「**教学内核**」不是「生产工具」。

**真要用**：把切词时取到的词统一 `.lower()` 即可，一行的事。

### ⚠️ ② 不收数字

正则只取汉字和字母，所以：

```text
"2024年"   → 切成 ['年']       数字丢了
"iphone15" → 切成 ['iphone']   数字丢了
```

**改法**：正则加一段 `|\d+` 即可。

### ⚠️ ③ 中文**不切词**

正则按「连续汉字」切，所以：

```text
"机器学习和深度学习" → ['机器学习和深度学习']   （一整句算 1 个词）
```

真分词需要 `jieba` 这类专业库（第三方包），超出本作品范围。**本作品的价值是「词频计数的内核」，不是「中文分词器」。**

### ⚠️ ④ 无停用词过滤

"的、了、是、在" 这类高频虚词会被正常计入，在长中文文本里容易霸占 top N。要过滤得自己准备停用词表。

### ⚠️ ⑤ 一次只处理一个文件

不扫目录、不批量。
