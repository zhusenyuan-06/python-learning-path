### 第 1 题（E15）· 静默错误三件套

**判定：✅ pass（连对 1/2）—— ① 满分，② 栽在 `return` 和 `print` 的顺序上，③ 只答了一半**

你的作答：
```
① 1:缺了strip（）2：缺了reverse=True 3：缺了return或else
② w = w.lower().strip()

   return

③ 1:可以按照空格切分 2：排序正确了 3：会返回，不会被覆盖
```

**① 三个错全找到 —— 满分。**
`.strip()` / `reverse=True` / 缺 `return`（或 `else`），一处不落。

**② 改写基本对，但有一处「提示凭空消失」。**
你写的是：
```python

    return

```
`return` 一执行函数就结束了；下面那句 `print("未覆盖")` 缩进在 `if` 外面，**永远执行不到**。
→ 提示没了（**这题考的就是静默错误**，结果是你自己又造了一个）。

正确写法：把提示**当成返回值带出去**
```python
if 姓名 in contacts:
    return "未覆盖"          # ← 提示随返回值一起走
contacts[姓名] = {"电话": "13800000000"}
return "已写入"
```

> ⚠️ **11-05 你栽在同一个地方**（评语原话：「改完后提示凭空消失」）。两次同错。
> → 下次写 `return` 的同时，先问一句：**「我要把什么带出去？」**

**③ 答了一半。**
「1:可以按照空格切分 / 2：排序正确了 / 3：会返回，不会被覆盖」—— 这是**「改完凭什么对」**，答对了。
但**「原来为什么没报错」**那半没答。真答案：

> 这三处错误**全是静默的**：
> - 缺 `.strip()` —— `w.lower()` 语法完全合法，只是没删掉首尾空白
> - 缺 `reverse=True` —— `sorted()` 语法完全合法，只是排成了升序
> - 缺 `return` —— `if` 语法完全合法，只是照样往下执行了

> **Python 只拦「语法错」和「会抛异常的错」，这三样都不属于。所以它一次都没吭声。**

**你要养成的句式**：

### 第 4 题（E24）· open(path, 'w') 会先清空再写

**判定：✅ pass —— 且连对 2 次，这题毕业了**

你的作答：
```
① 'w'写模式，会先清空文件里的内容
② 内容 = json.dumps(tasks, ensure_ascii=False)
   with open(DATA_FILE, 'w', encoding='utf-8') as f:

```

**① ✅** 'w' 写模式，会先清空文件内容。
**② ✅ 完全正确**，而且是本题的标准解法。
**③ ⚠️「先备好了内容」** —— 答到了**顺序**，这正是解法的命门，但没展开因果链。

完整链条（值得背下来）：

```python
# ❌ 原来：崩溃点在 with 块里面
with open(DATA_FILE, 'w', encoding='utf-8') as f:   # ① open 执行 → 文件被【清空】
    f.write(json.dumps(tasks))                      # ② json.dumps(tasks) → NameError → 崩溃
# ③ 崩溃时，文件已经是 0 字节了
```
**清空发生在 `open()` 执行的那一刻（还没进 with 块）**，而 `json.dumps(tasks)` 是在 with 块**内部**才求值的。
所以顺序是：**先清空 → 后崩溃**。

你改成的：
```python
内容 = json.dumps(tasks, ensure_ascii=False)       # ① 先算；算不出来就在这崩，文件还没被动
with open(DATA_FILE, 'w', encoding='utf-8') as f:   # ② 拿到能算出来的内容了，才敢开文件清空
    f.write(内容)
```
**改完凭什么对**：因为崩溃点被**挪到了 open 之前** —— 万一 `tasks` 没定义，现在崩，**旧文件还是完整的**。

### 第 6 题（E35）· dict.values() 恒为真

**判定：❌ fail —— ① 找对了原因，②「我不会改」，③ 留空**

你后来补做了①：
```
if d.values():  这一行返回的视图对象，不是列表，所以下一行就会是永远为真
```
**① 完全正确** ——「视图对象」「永远为真」两个关键词都抓到了，这正是本题的根。
但 ② 你写的是「我不会改」、③ 留空 → 仍是 **fail**（连对清零 0/2，犯次升到 2 → 进必考区）。

> ⚠️ 这题**不重复记 fail**（上一轮已经记过一次），你这次补做的结果与上次一致，
> 所以犯次停在 2，不会虚增。

**这题的核心，就一句话：**
```python
bool(d.values())    # 永远 True，只要字典非空
```
因为 `values()` 返回的**不是列表**，是一个**视图对象（view）**。
视图对象自己**永远不为空**，它只代表「这个字典的值的集合」，不告诉你里面有没有东西。

**正确写法：**
```python
def 是否全为零(d):
    return all(v == 0 for v in d.values())   # ✅ all() 逐个检查，每个值都得是 0
```
- `all()` 的语义是「**里面每一项都是真**」→ 只要有一个非 0 就返回 False。
- 想真的拿到列表：`list(d.values())`。
- `d.keys()` 同理，也是永远为真的视图。

**为什么原来没报错**：视图对象是**合法的 Python 对象**，`if 视图对象:` 语法完全成立。
Python 只知道「非空对象为真」，它不知道你想问的是「里面的值是不是全为 0」。
→ **静默错误**：LeetCode 官方那 2 个用例你还能蒙对，要到 `t` 是 `s` 的真子集时才暴露。

> 💡 这题和 E40 是同一个家族：**你问的是「A 里面有没有 B」，Python 回答的是「A 这个对象是不是非空」。**
> 下次遇到 `if xxx:` 判空，先问一句：**xxx 是个列表/集合，还是个「容器本身」？**

```python
# 要对齐再加宽度：f"{文件名:<12} | {主名:<12} | {扩展名}"
```

**为什么原来没报错**：`f"..."` 里的 `{}` 才是插值位置。这条字符串里**一个 `{}` 都没有**，
所以它就是个**普通字符串**，`f` 毫无作用 —— 但 `f"普通字符串"` 是**完全合法的语法**，
所以 Python 一次都没吭声，只是把字面量原样打印了 4 行。

> ⚠️ 补一个坑：`f"{"a"}"` 在 Python 3.12+ 才合法（旧版本要写 `f"{{'a'}}"` 或转义）。
> 你的 Python 3.12.7 没这个问题，但**换环境/面试时这是个雷**。
