# 错题追踪器

> 支撑「每周四复习同一个问题，直到它不再出现」

我自己的错题池系统。**这不是练习，是我给自己造的复习工具。**

> 这个是我主动要求建的，但是我并没有想到它的用处这么大，本来只是想看看我的错题，结果给了我意外之喜

建它的日期：**2026-10-22**（大复习那天，commit `c184cd4`）。

---

## 为什么建这个

那天做 10 月的第二次大复习，我发现一个很别扭的事实：

**"我以为我已经会了"和"我真的会了"是两件事。**

同一个错，10-21 犯了，10-22 又原样犯了一遍 —— 而两次之间我只隔了一天，写完还自己检查过。

问题出在哪儿？出在**我复习的方式全凭记忆**。翻笔记的时候，看到"我记得这个坑"就跳过去了。但"记得"和"改掉"之间隔着一次真正的重做。

所以我把这套复习做成了工具：**它不问我"还记不记得"，它每周四把题端到我面前，让我重写一遍。**

---

## 功能

11 个命令，覆盖「登记 → 出卷 → 作答 → 判定 → 退场」全流程：

| 命令 | 作用 |
|---|---|
| `ls` | 待复习清单（按优先级排序） |
| `stats` | 统计概览 + 顽固问题 TOP |
| `plan N` | 生成本周复习卷（含错/对代码对照）；**默认带「本周新错区」**，总题数恒为 N |
| `show E01` | 看某题详情（错写法 / 对写法 / 出处 / 复习流水） |
| `add "标题" "错误写法" "正确写法" "标签"` | 登记新错题 |
| `record E01 pass\|fail ["备注"]` | 记录一次作答结果 |
| `pending E01 ["备注"]` | 复习卷已出、还没作答时记一笔 |
| `regress E01` | 已掌握的题又犯了 → 重新激活 |
| `skill "标题" "来源JD"` | 登记能力缺口（从 JD 里读出来的、你不会的） |
| `skills` | 能力缺口清单 |
| `render` | 重新生成 `错题追踪.md` |

## 核心设计

```python
# 每条错题有 occurrences（累计犯过几次）。犯得越多，复习时优先级越高。
# 连续答对 streak 次才算「已掌握」，从复习池里退场（不再占用每周时间）。
# 已掌握的问题一旦再犯 → regress → 重新进池，而且通关门槛 +1（上限 4）。
#   越容易反复，收得越严 —— 这是「直到不再出现为止」的机制。
```

三条规则串成一条完整链路：

```
犯过 → 进池 → 每周四必考 → 连对 2 次才算掌握、退场
                                  ↓
                              再犯一次
                                  ↓
                        立刻重新激活，且门槛 +1（上限 4）
```

**"越容易反复，收得越严"** 是整个系统的关键。E15 那个错我犯过 5 次，第一次只要求连对 2 次，现在要求连对 4 次 —— 因为它顽固，就得用更狠的考核逼它真的改掉。

---

## 技术点

- **状态机**：`active` / `mastered` 两态 + `streak` 连续答对计数。答错 → `streak` 归零；`mastered` 的题再答错 → 变回 `active` 且 `need + 1`
- **JSON 持久化**：`json.dump(..., ensure_ascii=False, indent=2)`
  - **不这么写会怎样**：漏掉 `ensure_ascii=False`，所有中文题目标题变成 `"\u9759\u9ed8\u9519\u8bef..."` —— 中文直接报废
- **两段式排序**实现「高频优先，次数相同则最近优先」：
  ```python
  a = sorted(items, key=lambda x: x["last_seen"], reverse=True)
  return sorted(a, key=lambda x: x["occurrences"], reverse=True)
  ```
  先按最近一次排一遍，再按次数做一次**稳定排序** —— 相同次数的，相对最近的留在前面
- **`next_id` 不只靠 `max()`**：
  ```python
  # 注意：不能只靠 max()，因为并发写入（比如自动化任务和我同时登记）
  # 可能导致同号。这里扫描全部 E 数字取最大值，并额外检查候选号是否已被占用。
  ```
  扫全表取最大编号，再逐个检查占用 —— 避免撞号
- **`pending` 命令：复习卷已出但还没作答时，只记流水，不动 `streak`**
  - **不这么写会怎样**：出卷就当成"考过了"，连对次数虚报，错题提前退池 —— 那这个系统就成了自欺欺人的工具
  - 现在流水里能同时看到 `pending` 和 `pass`，**过程是透明的**

## 它真的有用吗 —— 看数据

> 有好多个静默错误都是靠这个记住的，就比如那个if后没有else或者return

E01 的完整流水，是这个系统最有说服力的地方：

```text
复习流水:
  2026-10-21  fail     通讯录题：提示未覆盖但实际覆盖了
  2026-10-22  fail     10.22复习.py 原样重犯，输出确实被覆盖
  2026-10-22  explain  已在 10.20练习.py 4.11 补记错/对对照
  2026-10-22  pending  10-22 周四大复习卷 第3 题已出，待作答
  2026-10-22  pass
```

**看这五行在讲什么：**

1. `fail` —— 10-21 第一次犯，记下来
2. `fail` —— 隔一天原样重犯（**如果只靠记忆复习，这一次会被跳过**）
3. `explain` —— 我在 `10.20练习.py` 里补了错/对代码对照，把这个错和它的解法写在一起
4. `pending` —— 复习卷出了，这题还没作答，**不虚报连对次数**
5. `pass` —— 这次答对了

**如果 10-22 那次没被"抽出来考"，E01 到现在还是"我以为我会了"的状态。**

现在它的状态是 `active | 犯过 3 次 | 连对 1/2` —— 还差一次才算掌握。门槛没到就是没过。

## 顺带长出来的能力：能力缺口清单

`skill` / `skills` 两个命令是后加的 —— 我开始看真实 JD 之后，发现「我不会的东西」和「我犯过的错」是两种不同的东西：

- 错题 = **已经暴露过**的坑（代码跑过才知道）
- 能力缺口 = **还没暴露**的坑（因为压根没写过那类代码）

所以错题追踪器后来多了一本账：

```text
能力缺口清单（从 JD 里读出来的、你还不会的）
==================================================
  S01   FastAPI 写 GET 接口
        来源: 某某JD
```

同一个工具，两本账：**已犯的错**和**还没犯但迟早会犯的错**。
