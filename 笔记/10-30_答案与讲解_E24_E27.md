## 练习 1 参考答案

### 标准写法（写法 C · 原子替换）

```python
def save_tasks(tasks, path="todos.json"):
    """把 tasks 列表安全地写进 path：任何一步崩溃都不破坏旧数据。"""
    tmp = path + ".tmp"                    # ① 临时文件，和正式文件同目录
    try:
        with open(tmp, "w", encoding="utf-8") as f:
            f.write(json.dumps(tasks, ensure_ascii=False))   # ② 只写临时文件
        os.replace(tmp, path)              # ③ 写成功了才替换正式文件（原子）
    except Exception:
        if os.path.exists(tmp):
            os.remove(tmp)                 # ④ 崩了清掉临时文件，别留垃圾
        raise                               # ⑤ 把异常抛出去，让调用方知道没存成功
```

### 逐条对照你写的

| # | 要求 | 标准答案里的对应 | 漏了会怎样 |
|---|---|---|---|
| ① | 原子替换 | `tmp` + `os.replace` | 退回写法 A/B，崩溃仍会毁数据 |
| ② | 崩了不毁数据 | 先写 tmp，最后才 replace | 直接 `open(path,"w")` = 0 字节 |
| ③ | 不留垃圾 | `except` 里 `os.remove(tmp)` | 目录里堆一堆 `.tmp` |
| ④ | 路径可指定 | 参数 `path="todos.json"` | 没法在临时目录里测 |
| ⑤ | **异常要抛出去** | `raise` | ⚠️ **最容易被漏的一条** |

### ⚠️ 第 ⑤ 条单独强调：`raise` 为什么不能省

```python
    except Exception:
        os.remove(tmp)
        # ❌ 少了 raise → 异常被吃掉，函数【正常返回】
```

少了 `raise`，`save_tasks` 会「假装成功」地返回 `None`。
调用方看到「没抛异常」，以为存好了，其实文件还是旧的。
**这又是一个静默错误** —— 和 E24 本身一个性质。

> 📌 **判断标准：函数没干成的事，不能装作干成了。**
> 「存盘失败」必须让调用方知道。

### 写法 A 也能过验收吗？

```python
def save_tasks(tasks, path="todos.json"):
    内容 = json.dumps(tasks, ensure_ascii=False)    # 先算
    with open(path, "w", encoding="utf-8") as f:     # 后开
        f.write(内容)                                # 再写
```

**能扛住「json.dumps 崩」**（崩在 open 之前，文件没被碰过），
所以练习 1 自测的检查 ① 也会过。

**但它扛不住「写到一半断电/磁盘满」**：
`open('w')` 已经清空了文件，`f.write` 写到一半失败 → 文件是残缺的。

| | 写法 A | 写法 C |
|---|---|---|
| 逻辑错误导致崩溃 | ✅ 旧数据完好 | ✅ 旧数据完好 |
| 写到一半失败（断电/磁盘满/进程被杀） | ❌ 旧数据已清空，文件残缺 | ✅ 旧数据完好 |
| 临时文件残留 | 无 | 需 `except` 清理 |

> 📌 **写法 A 解决「顺序」问题，写法 C 解决「原子性」问题。**
> 练习 1 明确要求 `os.replace`，所以标准答案是 C。

### ② + ③ 抽出来的函数 + 改写后的两个函数

```python
def save_tasks(tasks, path=DATA_FILE):
    """把 tasks 列表写进磁盘文件。

    这是【唯一】一份写文件的代码。
    其它地方一律调用它，不复制粘贴。
    """
    with open(path, "w", encoding="utf-8") as f:
        f.write(json.dumps(tasks, ensure_ascii=False))


def add_task(tasks, text):
    """加一条任务，并存盘。"""
    tasks.append({"text": text, "done": False})
    save_tasks(tasks)          # ← 调用，不复制
    return tasks


def mark_done(tasks, n):
    """把第 n 条任务标记为已完成，并存盘。"""
    if not isinstance(tasks, list):
        return "错误：tasks 必须是列表"
    if not isinstance(n, int):
        return "错误：n 必须是整数"
    if n < 1 or n > len(tasks):
        return f"错误：n 必须在 1~{len(tasks)} 之间"

    tasks[n - 1]["done"] = True
    save_tasks(tasks)          # ← 调用，不复制
    return tasks
```

### ④ 验收

```
改完后全文 with open 出现的次数：1（在 save_tasks 里）
原来两处重复的代码：删了
```

**注意：`save_tasks` 里的 `with open` 本身要不要用写法 C？**

严格说，**要**（那就等于把练习 1 和练习 2 合起来了）。
但今天这两道练习是**分开练的**：
- 练习 1 专门练 E24（怎么写才安全）
- 练习 2 专门练 E27（怎么抽才不重复）

**最佳答案是把两者合并**：

```python
def save_tasks(tasks, path=DATA_FILE):
    """写文件（写法 C：原子替换）。全文件唯一一份。"""
    tmp = path + ".tmp"
    try:
        with open(tmp, "w", encoding="utf-8") as f:
            f.write(json.dumps(tasks, ensure_ascii=False))
        os.replace(tmp, path)
    except Exception:
        if os.path.exists(tmp):
            os.remove(tmp)
        raise
```

> 📌 **这就是今天两道练习的汇合点：**
> **一份代码，同时解决「顺序」和「重复」两个问题。**

### ❌ 常见的几种「假答案」

| 写法 | 为什么不行 |
|---|---|
| 把两处代码改成调用，但**函数本身还是用 `open(path,'w')`** | 抽了重复，但没解决 E24 的安全问题 |
| 抽了函数，但**旧的两处还留着**（只是不用了） | 没真删。下次改的时候还是会有两份 |
| 抽了函数，但**函数里没有 `ensure_ascii=False`** | 中文变 `\uXXXX`（E21） |
| 把 `add_task` 改成「只改内存，不存盘」 | 改变了函数职责。存盘交给调用方决定也行，但要一致 |

## 三、两道题串起来的复盘

| | 练习 1 | 练习 2 |
|---|---|---|
| 表面在做 | 让写文件变安全 | 让重复代码变一份 |
| **实际在练** | **E24：把「清空」和「写入」分开** | **E27：让「改动」只有一份** |
| 一句话 | **顺序** | **单一来源** |

> 📌 **今天最该带走的一句：**
>
> **写文件 = 先准备好，再落盘（E24）。**
> **改代码 = 先列清单，再动手（E27）。**
>
> 这两条其实是同一条原则：
> **别让「破坏性的动作」发生在「还没准备好」的时刻。**
> `open('w')` 是破坏性动作 → 排在最后；
> 「删代码」是破坏性动作 → 先列清单。
