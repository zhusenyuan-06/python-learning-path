## 二、这周最大的 3 个进步

> 💡 写"从哪到哪"，不写"我学会了 XX"。  
> 例：❌「我学会了 Git」 ✅「10-23 只会 commit 不会 push，现在能独立把仓库推到 GitHub 并处理 IP 被墙问题」

1. **从「一次失败就崩」到「知道哪些错值得重试」**
   - 11-11 的 05/06：网络抖一下，程序就带着一串红字直接死掉
   - 11-14 的 08/09：能分清「该重试」和「白重试」—— **4xx / JSONDecodeError 一律不重试**（我请求写错了，重试一万次结果一样），**5xx / 429 / 网络层错误才重试**，而且退避 1 秒 → 2 秒，不是立刻重发
   - 判据落在两个维度上：**错误类型**（是不是网络层）+ **状态码区间**（4xx 还是 5xx）
   - 自测 4 个场景的尝试次数全部符合预期（正常 1 次 / 404 1 次 / 500 3 次 / 域名不存在 3 次）

2. **从「一次性的代码」到「换个场景还能用的函数」**
   - 06 的 CSV 落盘是**贴死**的：文件路径写死、表头写死，换个 API 就得整段重抄
   - 09 的 `存成CSV(数据行, 文件路径, 表头)` 把**三处硬编码全变成参数**
   - 这才是「作品化」的第一层含义 —— 不是多加几个功能，是**让代码换个场景还成立**
   - 配套一条习惯：写完立刻读回来核对，**不做「只写不验」**

3. **从「错误就是错误」到「错误是分层的」**
   - 异常有父子关系：`JSONDecodeError` / `HTTPError` 都是 `RequestException` 的子类，**except 必须子类在前、基类在后**，放反了子类分支永远执行不到
   - 返回值升级成 4 位 `(状态码, 数据, 类型名, 详情)` —— **类型名给机器判断，详情给人看**（这条是 E40，我自己推出来的）
   - 还有一个今天新学的：**返回值的个数也是契约的一部分**。主流程写的是 `表格行, 表头 = 取新闻()`，函数只还一个值就会 `TypeError` 崩掉

> 📌 备选（如果觉得上面三条有重复，可以换掉其中一条）：
> **从「每天都在欠账」到「能诚实地给欠账排序」** —— 11-11 建立的「阻塞效应 > 工时」原则，本周已经实际用上：本周那两笔看着是「3 笔 6.5 小时」，实际是「1 笔 2 小时的正则 + 1 笔连带」。

## 三、这周踩的坑（新增进错题追踪的）

| 坑       | 一句话说清错在哪                                                                                         | 现在怎么防                                                         |
| ------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| **E35** | `d.values()` 返回的是**视图对象**不是列表，字典非空就永远为真 → `if d.values()` 判空恒为 True，LeetCode 官方用例还能蒙对            | 要判空用 `len(d) == 0`；要判"全 0"用 `all(v == 0 for v in d.values())` |
| **E36** | 判断条件**查错了对象**：`ch`（字符）当成计数用 → `ch <= -1` 触发 TypeError                                            | 写条件前先问"这个变量是什么类型、装的是什么"                                       |
| **E37** | f-string 里**一个 `{}` 都没有** → f 只是个标记，整行原样打印，看着像跑成功了                                               | 写完 f-string 扫一眼：有没有插值？没有就别加 f                                 |
| **E38** | 算完了不 print → 结果只活在内存里，屏幕上一片空白                                                                    | 每个"算出结果"的下一行必须是 print                                         |
| **E39** | `timedelta.days` **只算完整天数**，零头在 `.seconds` 里                                                     | 要精确时长用 `total_seconds()`                                      |
| **E40** | 返回值里&#x653E;**「给人看的句子」**&#x800C;不是「给机器判断的标识」→ `错误类型 == "JSONDecodeError"` 拿一句描述比类型名，**永远 False** | 会被 `if` 拿去比较的值，必须是稳定标识；字符串给人看，结构给机器判                          |
| ~~E41~~ | 一行无用 `import` 让整个脚本在第 7 行就崩，后面的代码一行都跑不到 → 排查方向直接跑偏（以为是自己逻辑写错）                                    | 报错先看**报在第几行**，那是崩溃点，不一定是出错的那行逻辑                               |

> ⚠️ 新坑**当天就得登记进 `错题追踪.md`**，否则复习池里没有它，就等于白踩。  
> 📌 本周 7 个坑，**6 个进了池子**（E35~E40），E41 按你的要求**已从池中彻底删除**（但排查思路保留在本表）。
