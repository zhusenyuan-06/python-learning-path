# 通讯录 CLI

命令行版通讯录，支持增删改查和统计。

我学完 dict 和函数封装后写的第一个完整项目。规模不大，但每个函数都是自己拆的，跑通那一刻比学语法爽。

---

## 功能

- [x] 查询：按姓名查电话/地址/邮箱
- [x] 添加：新增联系人，重复不覆盖
- [x] 删除：删除并回显被删信息
- [x] 统计：列出没填邮箱的人
- [x] 展示：双层遍历打印全部

## 技术点

- **dict 套 dict 的嵌套结构**：外层 key 是姓名，value 又是一个 dict（电话/地址/邮箱）
- **函数封装**：5 个函数，各自职责单一
- **安全查询 `.get(k, default)`**：人不在先用 `.get()` 拿到 `None` 并判断，字段没填再用 `.get(k, default)` 兜底
  - **不这么写会怎样**：人不在的时候直接报错，程序就崩了。用 `.get` 拿不到就是 `None`，判断一下返回"查无此人"，程序还能接着跑下去。
  - **现在这么写**：查不到人和查不到字段是两种情况，各配一个兜底，返回给用户的提示也不一样。
- **防止覆盖**：先判断再写入（`if 姓名 in lianxiren: return ...`）
- **循环变量不泄漏**：`for 姓名, 信息 in ...` 不会污染全局命名空间

## 我踩过的坑（这里最值钱）

### 坑 1：if 后面漏了 return，提示了"未覆盖"却照样覆盖了

这是我做通讯录「添加联系人」那题时真犯过的错 —— 同一个错前后犯了 3 次（10-21 首犯，10-22 复习时原样重犯）。

```python
# ❌ 错的写法
def a(name, p):
    if name in contacts:
        print("已存在，未覆盖")
    contacts[name] = {"电话": p}   # 照样覆盖了！
```

**错在哪**：if 后面没有 else 或者是 return，代码照样往下走。`print` 只是把"已存在，未覆盖"这句话显示出来了，程序却根本不知道"这里该停"，于是接着执行下一行，把老数据直接覆盖掉。

最坑的是**输出看着没毛病** —— 屏幕上明明打了"未覆盖"，数据却已经被改了。这种错不报错，测试时特别容易滑过去。

```python
# ✅ 改对之后 —— 这就是 contact_book.py 里现在 `添加()` 的写法
def 添加(姓名, 电话, 地址, 邮箱=""):
    if 姓名 in lianxiren:                # 防覆盖：先看有没有
        return f"{姓名} 已经在通讯录里了，未覆盖"
    信息 = {"电话": 电话, "地址": 地址}
    if 邮箱:                             # 只有填了邮箱才加这个字段
        信息["邮箱"] = 邮箱
    lianxiren[姓名] = 信息
    return f"已添加 {姓名}"
```

我复习流水里记的（原样摘自自己的错题本）：

```
2026-10-21 🔴 错　通讯录题：提示未覆盖但实际覆盖了
2026-10-22 🔴 错　10.22复习.py 原样重犯，输出确实被覆盖
```

**现在我的习惯**：现在遇见了 if，我第一件事就是看有没有 else 或者 return，没有就要考虑是不是我的代码写错了。
