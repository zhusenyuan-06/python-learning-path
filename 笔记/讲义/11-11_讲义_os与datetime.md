## 一、这两个模块到底解决什么问题（大白话）

| 模块 | 一句话 | 什么时候用 |
|---|---|---|
| `os` | **跟操作系统打交道的接口** | 找文件、建目录、删文件、读环境变量 |
| `datetime` | **跟时间打交道的接口** | 现在几点、怎么排版、两个时间差多少 |

**它俩不是新东西，是把「你手动做的那些事」变成一行代码：**

| 你手动做的事 | 对应代码 |
|---|---|
| 在资源管理器里找文件 | `os.listdir()` / `os.walk()` |
| 新建文件夹 | `os.makedirs()` |
| 看文件多大、什么时候改的 | `os.path.getsize()` / `os.path.getmtime()` |
| 在文件里搜路径 | `os.path.join()` / `os.path.splitext()` |
| 看「今天几号」 | `date.today()` / `datetime.now()` |
| 在文件名后面打时间戳 | `datetime.now().strftime("%Y%m%d_%H%M%S")` |
| 「这份日志是 7 天前的吗」 | `timedelta(days=7)` 比较 |

**和已有知识的关系：**

- `os.path` ↔ 你在 11-02 学的 `pathlib` —— **同一件事的两种写法**。
  `pathlib` 更现代、更省心（11-03 你已经用熟了）。
  `os.path` 的**独有价值**是：`os.walk()` 递归遍历、`os.path.getmtime()` 文件时间戳、
  `os.environ` 环境变量 —— 这三样 `pathlib` **没有**（pathlib 有 `stat().st_mtime`，但没有 `walk` 和 `environ`）。
- `datetime` ↔ 下游的「提取日期」 —— **字符串变时间对象的唯一入口就是 `strptime`**。

## 二、os 常用（8 个，够用就行）

### 2.1 `os.getcwd()` vs `__file__` ★ 最重要的一条

```python
import os
from pathlib import Path

os.getcwd()            # 程序「当前工作目录」= 你敲命令时所在的目录
Path(__file__).parent  # 脚本文件自己所在的目录
```

**实跑输出（在我的机器上）：**

```
os.getcwd()          = D:\AI应用工程师\01-学习仓库-Python学习路径\pythonProject\练习
__file__             = D:\AI应用工程师\01-学习仓库-Python学习路径\pythonProject\练习\_参考样例_os_datetime语法.py
Path(__file__).parent = D:\AI应用工程师\01-学习仓库-Python学习路径\pythonProject\练习
```

> ⚠️ 这里两个值**恰好一样**，是因为我 `cd` 到练习目录才跑的。
> 你 11-04 踩的坑就是这个：在 C 盘目录里运行 `.\.venv\...\python.exe`，
> 当时 `getcwd()` 是 C 盘，脚本却在 D 盘 —— **相对路径全指错地方**。

**📌 一句话记忆**

> **想操作文件，用 `__file__` 定位；`getcwd()` 只用来「打印我在哪」。**
> 相对路径 = 相对于**当前工作目录**，不是相对于脚本。

### 2.2 `os.path.join()` —— 拼路径，但有个吃掉路径的坑

```python
os.path.join("输出", "a.txt")      # → 输出\a.txt
os.path.join("D:/x", "y/z.txt")    # → D:/x\y/z.txt
os.path.join("输出", "/a.txt")     # → /a.txt        ← 前面的被吃掉了
os.path.join("输出", "D:/x.txt")   # → D:/x.txt      ← 也被吃掉了
```

**📌 一句话记忆**

> **`join` 遇到「绝对路径」就把它当老大了，前面的全扔掉。**
> 想避免：`os.path.join("输出", 名)` 里保证 `名` 是纯文件名，不是路径。

> 💡 **这是我写讲义时自己写错的一条**：我凭印象以为会得到 `输出\D:/x.txt`，
> 实跑才发现是被吃掉了。**所以「拼路径的结果长什么样」不能靠想，要跑。**

### 2.3 `os.path.splitext()` —— 拆成「主名 + 扩展名」

**实跑输出：**

```
splitext('报告.pdf')   = ('报告', '.pdf')
splitext('a.tar.gz')   = ('a.tar', '.gz')
splitext('.gitignore') = ('.gitignore', '')     ← 扩展名是空的！
splitext('无扩展名')    = ('无扩展名', '')
```

**📌 一句话记忆**

> **`.gitignore` 这种「点开头」的文件，扩展名是空字符串 —— 整个文件名被当成主名。**

### 2.4 `os.makedirs()` vs `os.mkdir()` —— 建目录的两个坑

**实跑输出：**

```
mkdir 建多级 → FileNotFoundError : [WinError 3] 系统找不到指定的路径。
makedirs 建多级 → 成功
makedirs 再建一次（没写 exist_ok）→ FileExistsError : [WinError 183] 当文件已存在时，无法创建该文件。
```

**📌 一句话记忆**

> **`mkdir` 只建一层，父目录不在就报错；`makedirs` 能建多层，但重复建会报 `FileExistsError`。**
> → 所以标准写法永远是 **`os.makedirs(path, exist_ok=True)`**。

> 💡 这个 `exist_ok=True` 你在 11-11 上午的 api-demo 里已经用过了
> （`os.makedirs("输出", exist_ok=True)`）—— 当时是抄的，现在知道为什么了。

### 2.5 `os.walk()` —— 递归遍历目录树

**实跑输出（一个目录里有子目录）：**

```
根目录：...\_输出_os_datetime演示
  子目录：['子目录']
  文件  ：['说明.txt']
根目录：...\_输出_os_datetime演示\子目录
  子目录：[]
  文件  ：['里面的.txt']
```

**`os.walk()` 每次给你三个值：`根目录, 子目录列表, 文件列表`**

**📌 一句话记忆**

> **`walk` 是「先进去的先出来」—— 根目录在前，子目录在里，一层一层往下。**
> 要「处理所有文件」，就拿第三个值（文件列表）。

### 2.6 `os.path.getmtime()` —— 文件最后修改时间

**实跑输出：**

```
st_mtime（原始时间戳）= 1792670547.2686954
fromtimestamp 转换后  = 2026-10-22 20:02:27.268695
strftime 排版后        = 2026-10-22 20:02:27
```

**三步链条（很重要）：**

```
文件 → getmtime() → 浮点时间戳 → fromtimestamp() → 时间对象 → strftime() → 字符串
```

**📌 一句话记忆**

> **`getmtime` 给的是「一串数字」，不是日期 —— 必须过一道 `fromtimestamp` 才变成能读的时间。**

### 2.7 `os.listdir()` —— 顺序不保证

**实跑输出：**

```
listdir = ['子目录', '说明.txt']
```

**📌 一句话记忆**

> **`listdir` 返回的顺序是操作系统的（大概率按字母序），但【不保证】。**
> 要稳定顺序 → 自己 `sorted()`。

### 2.8 `os.environ` —— 环境变量

**实跑输出：**

```
环境变量总数：223
有 PATH 吗：True
取一个没设过的：（没设）
```

**用法：`os.environ.get("MY_API_KEY", "默认值")`**

**📌 一句话记忆**

> **API key / token 应该放环境变量，不写死在代码里 —— 写死了就等于发到 GitHub 上了。**
> （你 11-11 上午 api-demo 里没用 key，等做 LLM API 时这条就派上用场了。）

## 三、datetime 常用（6 个）

### 3.1 `now()` / `today()` / `date.today()` —— 三个「现在」

**实跑输出：**

```
datetime.now()   = 2026-11-11 13:42:01.618612   类型: <class 'datetime.datetime'>
datetime.today() = 2026-11-11 13:42:01.618612
date.today()     = 2026-11-11                    类型: <class 'datetime.date'>
```

**📌 一句话记忆**

> **`date` 只有「哪一天」，`datetime` 连几点几分都有。**
> 只需要日期就别用 `datetime`（少一堆没用的时分秒）。

### 3.2 `strftime()` —— 时间对象 → 字符串

**实跑输出（用固定对象 `datetime(2026, 11, 7, 9, 5, 3)` 验证）：**

```
%Y-%m-%d %H:%M:%S = 2026-11-07 09:05:03
%m = 11   %M = 05        ← ⚠️ 大小写差一个字母
%A 星期 = Saturday
isoformat() = 2026-11-07T09:05:03
```

**最常用的 6 个格式符：**

| 格式符 | 含义 | 实跑值 |
|---|---|---|
| `%Y` | 年（4 位） | 2026 |
| `%m` | 月（**小写**） | 11 |
| `%d` | 日 | 07 |
| `%H` | 时（24 小时制） | 09 |
| `%M` | 分（**大写**） | 05 |
| `%S` | 秒 | 03 |

**📌 一句话记忆**

> **`%m` 是月（month），`%M` 是分（Minute）—— 大写的是分钟。**
> 写反了**不会报错**，只会得到「11 月 5 日 11 月」这种鬼东西 → 典型的**静默错误**。

### 3.3 `strptime()` —— 字符串 → 时间对象 ★ 下游的关键

**实跑输出：**

```
strptime("2026-11-07", "%Y-%m-%d") = 2026-11-07 00:00:00
⚠️ 格式串写错 → ValueError : time data '2026-11-07' does not match format '%Y/%m/%d'
```

**📌 一句话记忆**

> **`strftime` 是「时间变字」，`strptime` 是「字变时间」—— 一对反义词。**
> 格式串写错 → **`ValueError`**（类型对，但值不合理）—— 就是错题池 E30 那个考点。

### 3.4 `timedelta` —— 算时间差

**实跑输出：**

```
终点 - 起点 = 10 days, 0:00:00
.days = 10   .total_seconds() = 864000.0
起点 - 终点 = -10 days, 0:00:00  .days = -10  .total_seconds() = -864000.0
差 1 小时 → .days = -1  .seconds = 82800  .total_seconds() = -3600.0
终点 + 7 天 = 2026-11-18 00:00:00
```

**⚠️ `.days` 的真实行为（我写讲义时凭印象写错过）：**

- 差 **10 天** → `.days = 10`（正常）
- 差 **-10 天** → `.days = -10`（**不是 -1**！我原来以为负数会变成 -1，错）
- 差 **1 小时** → `.days = -1`、`.seconds = 82800`

**📌 一句话记忆**

> **`.days` 只数「完整的天」，零头在 `.seconds` 里；负数会向下取整（-1 小时 = -1 天 + 82800 秒）。**
> **要精确到秒 → 一律用 `.total_seconds()`。**

### 3.5 `isoformat()` —— 存 JSON / 当文件名

**实跑输出：** `2026-11-07T09:05:03`

**📌 一句话记忆**

> **`isoformat` 是「标准格式」—— 存进 JSON 不会乱，排序也能按字符串排。**

### 3.6 ⚠️ 文件名里不能带冒号（两种写法，结果不一样）

**实跑输出（open 写法）：**

```
生成的文件名 = 导出_20261111_134316.csv
用 %H:%M:%S 直接当文件名 → PermissionError : [Errno 13] Permission denied: '...导出_2026-11-11 13:43:16.csv'
```

**但 pathlib 的 `write_text` 会写出另一回事（11-11 补充实跑）：**

```python
(DEMO / "报告:2026.txt").write_text("我是正文内容", encoding="utf-8")
```

**实跑结果 —— 报成功，但磁盘上根本没有这个文件：**

```
p.exists()                = True
os.listdir(DEMO)          = ['报告']        ← 只有「报告」，大小 = 0
(DEMO / "报告").read_text() = ''            ← 主文件是空的！
(DEMO / "报告:2026.txt").read_text() = '我是正文内容'   ← 内容跑到别处去了
```

**原因：Windows 的「备用数据流（ADS）」** —— 文件名里第一个冒号被当成了
「主文件名 : 数据流名」的分隔符。真实的主文件名是 `报告`，数据流名是 `2026.txt`，
内容被写进了那个数据流，**不是独立文件**。

| 写法 | 结果 |
|---|---|
| `open(路径, "w")` | 抛 `PermissionError` —— **明确失败，你能立刻发现** |
| `Path(路径).write_text()` | **报成功但内容丢了** —— 静默失败 ⚠️ 更危险 |

**📌 一句话记忆**

> **Windows 文件名不能有 `: * ? " < > |`。**
> 所以**文件名用 `%H%M%S`（无冒号），要给人看的才用 `%H:%M:%S`。**
> ⚠️ 并且**优先用 `open()` 写文件名相关的文件** —— 它会明确报错，
> 而 `write_text` 可能悄悄把内容写进 ADS，事后根本查不出来。
