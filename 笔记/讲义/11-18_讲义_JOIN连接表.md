## 1. 为什么需要 JOIN

前面学的都是**一张表里纵向筛**：

```sql
SELECT 序号 FROM 新闻 WHERE 星期 = '星期二'
```

但真实业务里，信息往往分散在多张表：

| 场景 | 表 A 有什么 | 表 B 有什么 | 共同键 |
|---|---|---|---|
| 电商 | 订单表（谁买了） | 商品表（买了什么） | 商品ID |
| 学校 | 学生表（谁） | 课程表（学什么） | 学号/课程号 |
| **本练习** | **新闻表（15 行）** | **星期对照表（5 行）** | **星期** |

JOIN 就是**用共同键把 A 和 B 横着拼成一张宽表**。

```
订单表                        商品表
┌──────┬────┬──────┐        ┌──────┬────────┬────┐
│订单号│商品ID│数量│   JOIN │商品ID│商品名称│价格│
├──────┼────┼──────┤  ═══>  ├──────┼────────┼────┤
│ 001  │ P01 │  2  │        │ P01  │ 键盘   │ 99 │
│ 002  │ P02 │  1  │        │ P02  │ 鼠标   │ 59 │
└──────┴────┴──────┘        └──────┴────────┴────┘
                    ↓ 拼完
┌──────┬────┬──────┬────────┬────┐
│订单号│商品ID│数量│商品名称│价格│
├──────┼────┼──────┼────────┼────┤
│ 001  │ P01 │  2  │ 键盘   │ 99 │
│ 002  │ P02 │  1  │ 鼠标   │ 59 │
└──────┴────┴──────┴────────┴────┘
```

## 2. 语法长什么样

```sql
SELECT 表A.列1, 表B.列2
FROM 表A
JOIN 表B ON 表A.共同键 = 表B.共同键
WHERE ...
GROUP BY ...
ORDER BY ...
```

本练习的库：

- `新闻` 表：15 行，列 = 序号 / 日期 / 新闻内容 / 星期
- `星期对照` 表：5 行，列 = 星期 / 编号 / 类型

共同键 = `星期`（两张表都有这一列，且列名相同）。

## 3. INNER JOIN vs LEFT JOIN（本题核心）

| | INNER JOIN（写 JOIN 就是它） | LEFT JOIN |
|---|---|---|
| 意义 | 两边**都**对得上才输出 | 左边**全部保留**，右边对不上填 NULL |
| 对不上的行 | **直接丢掉** | 保留，右边列为 NULL |
| 本练习结果 | **9 行**（休息日新闻被丢） | **15 行**（一行不少，6 行类型是 None） |

**为什么会有这个差别？** 因为 `星期对照` 表只录了 5 个工作日，休息日根本没录：

```
新闻表 15 行：  星期一×3  星期二×2  星期三×1  星期四×1  星期五×2  星期六×2  星期日×2
对照表 5 行：   星期一    星期二    星期三    星期四    星期五      （缺 星期六、星期日）

INNER JOIN →  两边都要有 → 15 - 6 = 9 行
LEFT JOIN  →  左边全要 → 15 行，其中 6 行的「类型」是 NULL
```

**什么时候用哪个？**

- INNER：只要两边都有信息的记录（统计"工作日新闻有多少条"）
- LEFT：左边的记录一条都不能丢（右边的信息是可选的，比如"没分类的商品也要显示"）

## 4. 四个必踩的坑

### 坑 1 · ON 两边列名必须一致

```sql
ON 新闻.星期 = 星期对照.名称    -- ❌ 对照表里没有「名称」这一列
```

报错：`no such column: 星期对照.名称`

**表名和列名用点号分开**：表名点列名，如 `星期对照.星期`。

### 坑 2 · SELECT 里两表同名列会打架

```sql
SELECT 序号, 星期 FROM 新闻 JOIN 星期对照 ON ...
-- ❌ ambiguous column name: 序号
```

两张表都有 `序号`？—— 不，这里两张表都有 `星期` 列，SQLite 报 `ambiguous column name: 星期`。

**解法：SELECT 里必须写全 `表名.列名`。**

### 坑 3 · NULL 不能用 `=` 比较，只能用 `IS NULL`

```sql
WHERE 星期对照.编号 = NULL      -- ❌ 永远不成立（不是"等于空"，是"未知"）
WHERE 星期对照.编号 IS NULL     -- ✅ 这才是"是空的"
```

**为什么？** NULL 的含义是"不知道"，`不知道 = 不知道` 在逻辑上还是不知道，所以返回不了 TRUE。

### 坑 4 · LEFT JOIN 的 WHERE 位置

```sql
FROM 新闻
LEFT JOIN 星期对照 ON 新闻.星期 = 星期对照.星期
WHERE 星期对照.类型 = '工作日'
```

这样写，LEFT 补出来的 NULL 行会被 WHERE 筛掉 → 结果跟 INNER JOIN 一样了。

**要保留 NULL 行，条件必须写在 ON 里**：

```sql
LEFT JOIN 星期对照 ON 新闻.星期 = 星期对照.星期 AND 星期对照.类型 = '工作日'
```

> 记忆：**ON 决定"能不能连上"，WHERE 决定"连上后留不留"**。

## 5. JOIN + GROUP BY 组合

昨天学的 GROUP BY 一样能用，只是表变宽了：

```sql
SELECT 星期对照.类型, COUNT(*) AS n
FROM 新闻
JOIN 星期对照 ON 新闻.星期 = 星期对照.星期
GROUP BY 星期对照.类型
ORDER BY n DESC, 星期对照.类型 ASC
```

**子句顺序是死的，不能换：**

```
SELECT → FROM → JOIN → ON → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT
```

⚠️ 注意：JOIN 出来的表**同样要写表名.列名**，GROUP BY 的分组列也一样。

## 6. Python 侧的写法（和上午一样）

```python
con = sqlite3.connect(库路径)
cur = con.cursor()
cur.execute("SELECT 新闻.序号, 星期对照.类型 FROM 新闻 "
            "JOIN 星期对照 ON 新闻.星期 = 星期对照.星期 "
            "ORDER BY 新闻.序号 ASC")
结果 = cur.fetchall()        # SELECT 两列 → 直接就是 list[tuple]，不用压平
con.close()
return 结果
```

**和上午 GROUP BY 练习的差别只有两处：**
1. SQL 里多了 `JOIN ... ON ...` 这一段
2. SELECT 的列要写 `表名.列名`

其余完全一样。

## 7. 建表与灌数据（CREATE TABLE / INSERT）

```python
cur.execute("CREATE TABLE IF NOT EXISTS 星期对照 ("
            "星期 TEXT PRIMARY KEY, 编号 INTEGER, 类型 TEXT)")

cur.executemany(
    "INSERT OR REPLACE INTO 星期对照 VALUES (?, ?, ?)",
    [("星期一", 1, "工作日"), ("星期二", 2, "工作日"), ("星期三", 3, "工作日"),
     ("星期四", 4, "工作日"), ("星期五", 5, "工作日")],
)
con.commit()
```

| 写法 | 作用 |
|---|---|
| `IF NOT EXISTS` | 表已存在也不报错（**幂等**，重复跑安全） |
| `TEXT PRIMARY KEY` | 主键，值不能重复 |
| `INSERT OR REPLACE` | 有同主键就替换，没有就插入 |
| `executemany` | 一次插多行，比循环 execute 快 |
| `con.commit()` | **必须提交**，否则数据不落盘 |

## 10. 三连击总结

| 概念 | 一句话 |
|---|---|
| JOIN | 用共同键把两张表横向拼成宽表 |
| INNER JOIN | 两边都对得上才输出（对不上的丢） |
| LEFT JOIN | 左边全保留，右边对不上填 NULL |
| `表名.列名` | 两表有同名列时必须写全 |
| `IS NULL` | 判断空值（不能用 `= NULL`） |
