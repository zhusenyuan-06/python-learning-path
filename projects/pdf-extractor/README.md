# 课件 PDF → 题库 CSV

**把一份 PDF 复习资料，自动拆成能刷的题库表。**

> **一句话**：读 PDF → 逐行认出「哪行是题干、哪行是选项」→ 存成 Excel 能直接打开的 CSV。

---

## 为什么做这个

作品①「课程问答 RAG 机器人」的 **ingest 层**干的就是这件事：把外部资料读进来、拆成结构化数据、存进本地知识库。

这个项目是那条链路的**第一块砖**——而且素材用的是**你自己真实的复习资料**（《计算机网络基础》复习题），不是玩具数据。

---

## 快速开始

```bash
cd projects/pdf-extractor

# 装依赖
python -m pip install -r requirements.txt

# 跑
python 01_提取PDF存CSV.py
```

跑完在 `输出/计算机网络基础_题库.csv` 得到题库表。

> ⚠️ **素材文件不在仓库里**（是版权资料，不能提交）。脚本从你的
> `~/Downloads/《计算机网络基础》复习 题-答案版.pdf` 读取，找不到会直接报错提示。
> 要换素材，改脚本顶部的 `素材PDF` 那一行即可。

## 代码结构

| 文件 | 干什么 |
|---|---|
| `01_提取PDF存CSV.py` | 主脚本。三步链路 + 异常处理都在这 |
| `requirements.txt` | 依赖（pymupdf） |
| `输出/` | CSV 产物 |

脚本里 8 个判断函数是核心，剩下都是配套：

| 函数 | 干什么 |
|---|---|
| `打开PDF` | 安全打开 PDF：素材缺失 / 文件损坏 / 有密码，三种分开报 |
| `提取所有行` | PDF → 所有非空行（带页码），`finally` 保证关句柄 ← **坑位 1 待填** |
| `是题目开头` | 判断一行是不是新题开头（**三道闸门**） |
| `是选项开头` | 判断一行是不是选项开头 |
| `拆开多选项` | 一行塞了多个选项时拆开 |
| `是页眉` | 拦掉「第N 页，共M 页」 |
| `拆成题目` | 按上面几个判断，把行组装成题 |
| `检查选项完整性` | 每题选项个数体检（超 4 个会报警，不静默丢数据） |
| `写成CSV` | 写文件（utf-8-sig，Excel 双击不乱码）← **坑位 3 待填** |
| `回读校验` | 读回来核对行数和表头 |
| `main` 里的校验 | 写完 CSV 后核对行数和表头 ← **坑位 2 待填** |

### `是题目开头` 的三道闸门

这是整个项目最容易写错的地方。**第一版我写宽了，解析出 32 道题**（假的），
加上三道闸门后才是正确的 13 道：

| 闸门 | 规则 | 挡掉了什么 |
|---|---|---|
| 1 | 题号只能 1~2 位数字 | `141.14.75.24` 里的 141、`255.255.192.0` 里的 255 |
| 2 | 数字后紧跟「、」或「.」，且「.」后不能再跟数字 | 小数 `2.2*108m/s` 里的 2. |
| 3 | 题号必须紧贴行首 | 句中出现的 `…网络地址为_ _141.14.64.0` |

正则：`r"^\d{1,2}\s*[、]|^[0-9]{1,2}\.(?!\d)"`

## 异常处理（v1.1，11-19 补）

**一条原则贯穿全部：宁可不产出，也不要产出一个假的结果。**

平时跑得好好的，出事的时候才知道这段代码值不值钱 —— 所以每种死法都配了
「人能看懂的原因」，而不是甩一个栈就跑了。

| 出的事 | 原来会怎样 | 现在会怎样 |
|---|---|---|
| 素材 PDF 不存在 | `assert` 报错，一行 AssertionError | 提示文件路径 + 告诉你改脚本哪一行 |
| PDF 损坏 / 不是 PDF | 裸抛 `FileDataError` 栈 | `❌ PDF 打不开` + 列出 3 种可能原因 |
| PDF 有打开密码 | **不报错**，给你一个空文档，一行字都读不到 | 专门查 `needs_pass`，明确说要先解密 |
| 某一页取文字失败 | 整篇报废 | 跳过这页继续，后面照跑 |
| 提取过程中途抛异常 | `doc.close()` 被跳过 → **Windows 上 PDF 被锁住**，下次跑报"文件被另一进程占用" | `close()` 放 `finally`，异常也保证关 |
| 输出目录（含父目录）不存在 | `FileNotFoundError` 裸崩 | `mkdir(parents=True)` 一路建出来 |
| CSV 正被 Excel 打开 | `PermissionError` 裸崩 | 直接告诉你「多半是 Excel 开着，关掉再跑」 |
| 一道题都没解析出来 | **假绿**：写出一个只有表头的空 CSV，回读校验还"通过"（0 == 0） | 直接报错退出，不产出任何 CSV |
| 选项超过 4 个 | 多出来的**静默丢弃**，丢完还不知道 | 打印警告，带题号和被丢的内容 |

配套测试：你自己写 `02_测试_异常处理.py`，用例清单见下节。写不出来时对照 `_参考答案_异常处理测试.py`（不进仓库）。

## 3 个关键实现（11-19 补）

异常处理的框架和提示都在代码里，这 3 个是有坑的地方，记住写法：

| # | 在哪 | 写法要点 | 为什么这么写 |
|---|---|---|---|
| **1** | `提取所有行` 的 `finally` 块 | `finally: doc.close()` | 写在 `for` 后面那一行的话，异常一抛就跳过了 → Windows 上 PDF 被锁住。⚠️ 老实说：当前"跑一次就退出"的用法下两种写法都能跑通，差别在 v2 批量处理多个 PDF、或同一进程内重复调用时才致命 |
| **2** | `main` 末尾的校验 | 不用 `assert`，改 `raise SystemExit(消息)` | `python -O` 会把 `assert` 全部跳过 → 校验等于没有，出错也不吭声，直接"成功"退出（假绿）。消息里要写出期望值和实际值 |
| **3** | `写成CSV` 的 `except PermissionError` | `raise SystemExit(...) from e` | Windows 上 CSV 被 Excel 打开着就写不进去，裸抛栈没人看得懂；`from e` 保留原始异常，排查能看到根因 |

写测试脚本的 3 个提示：
- 主脚本文件名是 `01_提取PDF存CSV.py`（开头数字 + 中文），**不能用 import 直接引**，要用 `importlib.util.spec_from_file_location` 按路径加载
- 加载后模块名别叫 `__main__`，否则主脚本的 `main()` 会自动跑起来
- 造临时文件用 `tempfile.TemporaryDirectory()`，别往项目目录里写垃圾

## 踩过的坑

- **页码从 0 开始**：代码里 `doc[0]` 是第 1 页，存进 CSV 要 +1
- **CSV 乱码**：写文件必须 `encoding="utf-8-sig"`，普通 `utf-8` 用 Excel 双击会中文乱码
- **PDF 里每页开头有换行**：不丢空行的话，题号判断会被空行打断
- **题号规则写太宽 → 32 道假题**：见上面「三道闸门」
- **选项可能挤在一行**：PDF 里有 `B、一对多通信C、面向报文`（B 和 C 挤一起）、
  `A．最大传输速率　　B．最长帧长　　C．最短帧长　　D．最大站点数`（4 个挤一行），
  必须按选项字母位置切开
- **选项也可能被换行**：`C、具有多个IP 地址，…相同的网络号，并` + `且占用一个主机号`
  是两行，第二行是 C 的续行，不是题干
- **页眉会污染题干**：`第2 页，共8 页` 必须单独拦掉，否则混进题 9 的题干
- **`sqlite3.connect` 路径写错会静默生成 0 字节假库**：connect 前先 assert 路径存在
- **`assert` 不能用来做校验**：`python -O` 会把 assert 全部跳过 → 出错时不报错、直接"成功"。
  现在全部换成显式 `if ... raise SystemExit(具体消息)`
- **`close()` 必须放 `finally`**：放最后一行的话，异常一抛就跳过 → Windows 上文件被锁住
- **`mkdir(exist_ok=True)` 不够**：父目录不存在照样 FileNotFoundError，得加 `parents=True`
- **同一个错在不同系统是不同异常**：Windows 上 `open(目录, "w")` 抛 `PermissionError`，
  Linux 上抛 `IsADirectoryError` → 写测试时两种都得认
