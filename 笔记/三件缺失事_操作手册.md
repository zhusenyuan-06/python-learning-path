## 一个作品必须有的 4 样东西

```
① 能跑的代码          ✅ 你有了
② README（说明白怎么用）   ⬜ 明天补
③ requirements.txt（依赖）  ⬜ 明天补
④ 部署链接 / 在线可访问   ⬜ 10-25 左右
```

## 具体操作

### 步骤 1：给每个项目建独立文件夹（明天做）

不要所有文件平铺在一个目录里。改成：

```
D:\pythonProject\
├── projects/               ← 新建，所有作品放这
│   ├── contact-book/       ← 通讯录
│   │   ├── app.py
│   │   ├── data.py
│   │   ├── requirements.txt
│   │   └── README.md
│   ├── word-counter/
│   │   ├── app.py
│   │   ├── 文本.txt
│   │   ├── requirements.txt
│   │   └── README.md
│   └── error-tracker/
│       ├── tracker.py
│       ├── errors.json
│       ├── requirements.txt
│       └── README.md
├── exercises/               ← 每日练习挪这
└── notes/                   ← 笔记挪这
```

**为什么**：GitHub 上一个 repo 一个项目，HR 点开就能看懂你在做什么。

### 步骤 2：写 README（每个项目一份）

**模板**（照抄填空即可）：

```markdown
# 项目名

一句话说清它干什么。

## 截图 / 效果
（放一段运行输出，或一张 GIF）

## 功能
- 功能 1
- 功能 2

## 怎么跑
```bash
pip install -r requirements.txt
python app.py
```

## 我学到什么
- 技术点 1
- 技术点 2

## 遇到的问题
（写你 debug 的过程 —— **这是加分项**，说明你在真实解决问题）
```

**关键**：最后两栏别省。**面试官最爱问"你遇到的最大问题是什么"**，你直接写在这了。

### 步骤 3：写 requirements.txt

通讯录用标准库 → 内容是：
```
# 本项目只用 Python 标准库，无需第三方依赖
# Python >= 3.10
```

用 Streamlit 的项目：
```
streamlit>=1.28
```

# 第 2 件：部署上线

## 为什么 AI 应用岗必须会这个

面试官问「你做过什么 AI 应用」：
- 「我写了 800 行」→ 对方要自己读半小时，且不一定能跑
- 「你点这个链接就能用」→ **5 秒钟建立信任**

**你的技术栈里有现成工具**：WorkBuddy 有 `sites` 技能，能把本地项目直接发布成在线链接。

## 具体操作

### 第 1 小节：推 GitHub（明天做，30 分钟）

#### 步骤 1：注册 + 配置（你来操作，我做不了）

1. 打开 https://github.com 注册（用你常用邮箱）
2. 右上角 → Settings → SSH and GPG keys / 或直接用 HTTPS

**然后在终端执行（把名字邮箱换成你的真名）**：
```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

> ⚠️ 我这次用临时配置提交了（`15816 / 15816@users.noreply.github.com`），
> **你必须改成真名邮箱**，否则 GitHub 不会把提交关联到你的账号。

#### 步骤 2：建仓库

**在 GitHub 网页上操作**：
1. 右上角 `+` → New repository
2. Repository name: `python-learning-path`（或 `python-projects`）
3. **不要勾** "Add a README"（本地已经有了）
4. 点 Create repository

#### 步骤 3：关联并推送（我可以帮你跑）

```bash
cd D:\pythonProject
git remote add origin https://github.com/你的用户名/python-learning-path.git
git branch -M main
git push -u origin main
```

**推送时 GitHub 会要求登录**：
- 密码框 → 填 **Personal Access Token**（不是登录密码！）
- 或用 GitHub Desktop / IDE 的图形化登录（**推荐这个，你 PyCharm 自带**）

> 💡 **PyCharm 里更简单**：Settings → Version Control → GitHub → 登录 → 然后 Commit 面板直接 push。

#### 步骤 4：以后每天 commit（1 分钟）

```bash
cd D:\pythonProject
git add .
git commit -m "feat: 10-23 通讯录 CLI 完成菜单功能"
git push
```

**commit message 写法**（GitHub 会显示在主页上，HR 会看）：
```
feat: 新功能
fix: 修 bug
docs: 改文档
refactor: 重构，不改功能
test: 加测试
chore: 杂事（改配置等）
```

### 第 2 小节：把作品变成链接（10-25 左右）

**最简单的路：Streamlit**

```bash
pip install streamlit
```

通讯录 CLI → 网页版，核心代码就几行：

```python
import streamlit as st
st.title("通讯录")
姓名 = st.text_input("姓名")
if st.button("查询"):
    st.write(查询(姓名, "电话"))
```

然后：
```bash
streamlit run app.py
```

**部署到线上**（WorkBuddy 的 `sites` 技能能直接做）：
- 我帮你把项目发布成链接
- 或者用 Streamlit Community Cloud（免费，绑 GitHub 仓库即可）

**3 个作品的部署优先级**：
1. 错题追踪器（成本最低，CLI 转网页最容易）
2. 通讯录（最能证明你会做完整项目）
3. 词频（最简单，但最像"练习"而非"作品"）

# 第 3 件：简历与投递

## 这一件不需要学任何新技术，只需要做

## 具体操作

### 第 1 小节：现在（本周）—— 看 JD，定方向

1. 去 BOSS 直聘 / 拉勾 / 智联，搜 **「AI 应用工程师」「大模型应用开发」「Python 开发」**
2. 存 **5 份 JD**（截图或复制文字）
3. 逐条列出要求，分三类：

| 类别 | 举例 | 怎么办 |
|---|---|---|
| **我已会** | Python、字典、文件读写 | 直接写进简历 |
| **我不会但要学** | FastAPI、RAG、向量数据库、LangChain | **记进错题追踪系统**（新增"能力缺口"类型） |
| **我不理解** | "Agent 编排"、"多模态"、"微调" | 去 BOSS 搜这个词，问清楚是干什么的 |

**这一步的价值**：你会发现**"我以为该学的"和"JD 上写的"不完全一样**。
按 JD 学，比按自己想象学，效率高 3 倍。

### 第 2 小节：扩展错题追踪系统（我来加）

现在追踪器只管「代码错题」。**加一个 `skills.json`**：

```json
{
  "skills": [
    {
      "id": "S01",
      "title": "FastAPI：写一个 GET 接口",
      "from_jd": "某某科技 AI应用工程师 JD",
      "priority": "high",
      "status": "todo",
      "notes": ""
    }
  ]
}
```

追踪器加两条命令：
```bash
错题追踪器.py skill "FastAPI 写 GET 接口" "某某JD"
错题追踪器.py skills        # 看能力缺口清单
```

**这样你的追踪系统就同时管两件事**：
- 代码错题（每周四复习）
- **能力缺口（决定你接下来学什么、简历上写什么）**

  · 错题追踪器（GitHub链接）—— 状态机设计、JSON 持久化、CLI 工具
  · 词频统计工具（GitHub链接）—— 文件读写、文本清洗、排序

【技能】
  Python（熟练：字典/列表/集合/函数/文件读写/异常处理）
  Git / GitHub（日常使用）
  SQL、HTTP、REST API（学习中）

【实习/实践】
  （有就写，没有就留空，别编）

【自我评价】  ← 一句话，别写"认真负责"这种废话
  习惯用数据验证代码正确性，有自建错题追踪与周复盘机制

**最后那行「自我评价」就是今天的错题追踪系统** —— 它比"认真负责"值钱 10 倍，因为它**具体、可验证、有产出**。
