## 第 1 题（E03 · 漏了 `.strip()`）

### 1-1 `.strip()` vs `.strip("，")`

**你的答案**：`strip()` 去空格，`strip("，")` 去空格还有逗号。
**实际**：两个都不干净。

| 原始 | `.strip()` | `.strip("，")` |
|---|---|---|
| `"  苹果，"` | `"苹果，"` ← 空白没了，逗号还在 | `"  苹果"` ← 逗号没了，**空格还在** |
| `"香蕉，"` | `"香蕉，"` | `"香蕉"` |
| `"  梨 "` | `"梨"` | `"  梨 "` ← **什么都没变** |
| `"橙子"` | `"橙子"` | `"橙子"` |

**规则**：

- `.strip()` 无参数 → 剥掉首尾**所有空白**（空格 / `\t` / `\n` / `\r` / 全角空格 U+3000）
- `.strip(chars)` → 剥掉首尾**属于 `chars` 这个字符集合**的字符。**空白不在集合里，就不剥**

所以 `.strip("，")` 只能剥逗号，剥不了空格。要一次剥干净，把要剥的字符**都列进集合**：

```python
w.strip(" \t\r\n，、。！？")     # "  苹果，" → "苹果"  ✅
```

或者两步：`.strip().strip("，")`

### 1-2 `"苹果，".strip("苹果，")` → `""` ✅ 你答对了

**但这个结果本身是个陷阱** —— `strip` 的参数是**字符集合**，不是**子串**：

```python
"好吃苹果".strip("苹果")   → "好吃"    ← 它把结尾的"果"也吃掉了
"苹果派".strip("苹果")     → "派"      ← 想删"苹果"两个字，结果把"苹果"也删了
```

**规则**：参数里写了哪些字符，**首尾的这些字符就会被逐个剥掉**，不管它们连不连成一个词。
→ **只把要剥的标点写进去，别把词本身写进去。**

### 1-3 `.strip()` 到底管什么

| | 管不管 |
|---|---|
| 首尾空白 | ✅ 管 |
| 中间空白 | ❌ 不管 |
| 首尾标点 | ❌ 不管（除非写进参数） |
| 首尾汉字 | ⚠️ 写了参数就管，而且会误伤 |

```python
"  你 好  世界  ".strip()  → "你 好  世界"    ← 中间的空格一个没少
```

### 一句话记忆

> **`strip` = 只管两头，不管中间；默认只管空白，不管标点；给了参数是「字符集合」，不是「要找的词」。**

## 第 2 题（E04 · 排序）

### 2-1 `sorted(库存, key=lambda x:x[1], reverse=True)` ❌

**这个写法有两种失败模式，取决于键是几个字：**

**模式 A —— 键里有单字（本题的"梨"）→ 直接崩**

```
IndexError: string index out of range
```

因为 `for k in 字典` 迭代出的是**键**，`x` 是字符串 `"梨"`，`x[1]` 越界。

**模式 B —— 键全是多字 → 不报错，但排出来的顺序是错的**

```
苹果[1] = 果    香蕉[1] = 蕉    橘子[1] = 子    橙子[1] = 子    西瓜[1] = 瓜
sorted(...) → ['香蕉', '西瓜', '苹果', '橘子', '橙子']    ← 按"第二个字"排的
```

**根因**：`sorted(字典)` 迭代出的是**键**，不是 `(键, 值)` 对。
想按**值**排，就必须先拿到键值对 → **加 `.items()`**：

```python
sorted(库存.items(), key=lambda x: x[1], reverse=True)
# [('香蕉',9), ('梨',7), ('苹果',5), ('橙子',5), ('西瓜',4)]   ✅
```

### 2-2 并列第 3 名被切掉了

排好后：`香蕉 9 > 梨 7 > 苹果 5 = 橙子 5 > 西瓜 4`
**第 3 名是并列的**（苹果和橙子都是 5）。

`正确[:3]` → `[('香蕉',9), ('梨',7), ('苹果',5)]` —— **橙子没了**。
**实际输出 3 种，期望 4 种。**

**这在真实场景里就是「TOP 3 排行榜漏了并列第 3 名」** —— 用户一眼看穿。

### 2-3 并列的正确修法：阈值法

把 `[:3]` 改成 `[:4]` 是**硬编码**，只对这一组数据成立。数据一变（比如 5 个都是 5）照样错。

**阈值法**：先算出第 N 名的分，再把所有 **≥ 这个分** 的全留下。

```python
前N = 3
排序后 = sorted(库存.items(), key=lambda x: x[1], reverse=True)
阈值 = 排序后[前N - 1][1]              # 第 3 名的分 = 5
结果 = [项 for 项 in 排序后 if 项[1] >= 阈值]
```

→ `[('香蕉',9), ('梨',7), ('苹果',5), ('橙子',5)]` ✅ **4 种**

> （还有 `itertools.groupby` 写法，等你学到 itertools 再展开）

## 第 3 题（E13 · 返回新值 vs 原地修改）

### 正确答案

```
abc ab
[1, 2, 3] [1, 2, 3]
[1, 2, 3] [1, 2]
```

你第 3 段答「和第二个一样」❌ —— **这正是 E13 要纠正的那一点**。

### 逐段拆

**第 1 段 · 字符串（不可变）**

```python
a = "ab"; b = a; a += "c"
```

`a += "c"` 展开是 `a = a + "c"` → **新建**一个字符串 `"abc"` 赋给 `a`。
`b` 还指着老的 `"ab"` —— 字符串不可变，只能新建。
→ `abc ab` ✅

**第 2 段 · 列表（可变）+ `+=`**

```python
x = [1,2]; y = x; x += [3]
```

`x += [3]` 对 list 展开是 `x.extend([3])` → **原地修改** `x` 那个列表对象。
`y` 和 `x` 是**同一个对象**（`x is y` → True），所以都变。
→ `[1, 2, 3] [1, 2, 3]` ✅

**第 3 段 · 列表 + `= +`**

```python
p = [1,2]; q = p; p = p + [3]
```

`p + [3]` **新建**了一个列表赋给 `p`。
`q` 还指着老的那个 `[1,2]`（`p is q` → False）。
→ `[1, 2, 3] [1, 2]` ✅

### 一张表记住

| 类型 | `+=` 的真实动作 | 别名会跟着变吗 |
|---|---|---|
| str / int / tuple | 新建再赋值 | ❌ 不变 |
| list / dict / set | **原地修改** | ✅ 跟着变 |

### 为什么这个坑危险（函数版）

```python
def 加一个(列表):
    列表 += [1]          # 原地改了调用方的列表！

def 加一个安全(列表):
    return 列表 + [1]    # 新建，不碰原列表
```

```python
我的 = [1]
加一个(我的)
print(我的)     # [1, 1]   ← 莫名其妙多了一个
```

**这就是「默认参数 `def f(x=[])`」那个经典坑的近亲。**

### 附带一条

```python
d = {}
d += {'a': 1}     # TypeError: unsupported operand type(s) for +=: 'dict' and 'dict'
```

dict 不支持 `+=`，要用 `d.update({'a': 1})`。

## 三道题其实是同一件事

| 题 | 表面现象 | 根子 |
|---|---|---|
| 1 | `strip` 没剥干净 | **你以为它做了两件事，它只做一件** |
| 2 | `sorted` 排错 | **你按值排，却只拿到了键** |
| 3 | `+=` 行为不同 | **你以为是同一个操作，其实是两个** |

**你错题池里 E15 的标题就是「静默错误三件套：能跑但结果是错的」。** 这三题是它的三个变体 —— 而且第 2 题还多一种：**能崩**。

**真正要改的不是背 API，是一个动作**：写完问一句
> **「这个函数/方法，它的参数和返回值到底是什么类型？它到底做了哪几件事？」**
>
> - `strip()` → 返回 `str`，参数是**字符集合**，只管首尾
> - `sorted(字典)` → 迭代给的是**键**，要键值对得 `.items()`
> - `+=` → 对可变/不可变是**两套语义**
