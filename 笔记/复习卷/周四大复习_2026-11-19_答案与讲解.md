### 第 1 题（E02）· 同一个变量名承担两种角色（被覆盖/泄漏）

**判定：❌ fail（连对清零）—— ① 满分，② 栽在缩进，③ 方向反了**

你的作答：
```
①
nums即是参数，又是计数器，counts开始是字典后面又被覆盖成了int，循环变量跑出了循环作用域，泄漏到外面
②
改写后的代码：
def sum_list(nums):
    total = 0
    for i in nums:
        total += i
    return total

for w, c in t.items():
    print(w, c)

   print(sum_list(b))
   print(c.items())
③
改名之后参数没有被覆盖成计数器，w和c各司其职没有出现字典被覆盖的情况，print缩进到循环内
```

**① ✅ 完全正确。** 三个错一个不漏，而且"同一个名字前后扮演两个角色"这个概括说到位了。
这是 E02 的题眼，你连续三卷都能满分找到。

**② ❌ 两个硬伤。**

你的 `sum_list` 改对了（`total` 独立命名，不覆盖入参）——**这是这题最关键的一处，你做对了**。
循环变量也改名了（`counts` → `c`），也对了。

但下面两行：

```python
for w, c in t.items():
    print(w, c)
    print(sum_list(b))     # ← 缩进进循环了
    print(c.items())       # ← 缩进进循环了，而且这行本身就不该留
```

**硬伤 1：print 被你缩进进了循环体。** 实跑结果：

```
python 3
27
>>> AttributeError: 'int' object has no attribute 'items'
```

`sum_list(b)` **被打印了 2 次**（循环 2 轮，每轮打一次）。期望是打 1 次。

**硬伤 2：`print(c.items())` 这行根本不该留。** 循环结束后 `c` 是最后一次迭代的**整数**（`"is"` 的次数 2），
所以 `c.items()` 必然 `AttributeError`。这行是原题用来暴露「循环变量泄漏」的**探针**，
改对之后它**必须被删掉**——留着它就是在测「你还会不会用错对象」。

正确版本：

```python
def sum_list(nums):
    total = 0
    for i in nums:
        total += i
    return total

for w, c in t.items():
    print(w, c)

print(sum_list(b))
```

实跑输出：
```
python 3
is 2
27
```
✅ 打印 2 轮循环内容 + 1 次求和，和期望完全一致。

**③ ❌ 说反了。** 你写「print 缩进到循环内」是修法——**恰恰相反，缩进进循环是新引入的 bug**。
正确说法是：**`print` 必须在循环外**（它不属于任何一轮，它要做的事在循环全部结束后才发生）。
缩进的语义是「这行属于这一轮」，你把「循环结束后才做的事」放进了「每一轮都做」里。

### 补充：这三个错其实是**一类错**

| 表面现象 | 深层 |
|---|---|
| `nums` 被覆盖成累加器 | 同一位置，类型变了（list → int） |
| `counts` 被顶成次数 | 同一位置，类型变了（dict → int） |
| 循环变量泄漏到循环外 | 名字跑出了它该在的作用域 |

**一句话**：Python 变量没有类型声明，名字是**贴标签**用的。
你可以在任何地方重新贴标签，但**贴之前先想清楚这位置该是什么标签**。
拿到变量名先问一句：**这位置它该是什么类型？**

### 第 2 题（E15）· 静默错误三件套

**判定：❌ fail（连对清零）—— ① 满分，② 直接 SyntaxError，③ 说错了 return 的语义**

你的作答：

```
②
（改了 w.lower().strip()、加了 reverse=True、加了 return）
③
有了.strip(),此可以被正确切分，排序正确了，有了return可以跳出循环
```

**① ✅ 三个全找到，而且描述精确。** "有 if 无 return，print 被强制执行"——**这一句是标准答案级别的表述**，
说明你真的知道问题在哪，不是蒙的。

**② ❌ 硬伤：`return` 写在了模块顶层。**

```python
姓名, 新电话 = "小明", "13911112222"
if 姓名 in contacts:
   print("未覆盖")
   return          # ← SyntaxError: 'return' outside function
contacts[姓名] = {"电话": 新电话}
```

实跑：
```
SyntaxError: 'return' outside function (Q2, line 15)
```

**整个脚本一行都没跑起来。** 这就是 E15 的连续第三次栽跟头：

| 日期 | 你写的 | 后果 |
|---|---|---|
| 11-05 | `return` 后还有 `print` | 提示凭空消失（不可达） |
| 11-12 | `return` 后还有 `print` | 同上，判 fail |
| **11-19（今天）** | `return` 在模块顶层 | **整个文件 SyntaxError** |

**根因（今天才真正暴露）：`return` 只能写在函数体内部。**
你写的这段是**模块顶层**——脚本直接执行的代码，不在任何函数里。Python 规定：
`return` 用来结束**函数**，顶层没有"要结束的函数"，所以直接语法错误。

标准答案里那句 `return "未覆盖"`，原题是**放在函数里**的：

```python
def 更新电话(姓名, 新电话):
    if 姓名 in contacts:
        return "未覆盖"
    contacts[姓名] = {"电话": 新电话}
    return "已更新"
```

所以本题**如果你只把 `return` 那行删掉**（让覆盖照常发生）也不完全对——
**这题真正要改的不是加 `return`，是让「不覆盖」这件事在函数里表达。**

**硬伤 2：`.strip()` 去不掉逗号。**

```python
w = w.lower().strip()      # 你的写法
```

实测两种写法的差别：

| 写法 | `hello` 次数 | `"hello,"` 是否单独存在 |
|---|---|---|
| `w.lower().strip()` | **1** | **是** |
| `w.lower().strip(".,!?")` | **2** | 否 |

`strip()` **默认只去空白字符**（空格、换行、制表符），**逗号、句号、问号、感叹号都留着**。
卷面期望是「`hello` 次数 = 2，且 `hello,` 不该单独存在」——你的写法达不到。

正确写法：`w = w.lower().strip(".,!?")`（把要去掉的字符**列出来**）。

**③ ❌ 两处不准确。**

1. **「有了 return 可以跳出循环」——错。** `return` 不是"跳出循环"，是**结束整个函数**。
   `break` 才是跳出循环。两者作用范围完全不同：
   - `break` → 只结束**当前这一层循环**，继续往下执行
   - `return` → **整个函数**立刻返回，函数后面的代码一行都不执行

2. **「有了 `.strip()` 此可以被正确切分」——不成立**（因为逗号还在，见上）。

**静默错误三件套的通用判据**（这题真正的价值）：

| 坏法 | 为什么不报错 | 后果 |
|---|---|---|
| 缺 `.strip(".,!?")` | `split()` 正常返回、`.strip()` 正常返回 | 词频算错 |
| 缺 `reverse=True` | `sorted()` 正常返回排序结果 | 排行榜方向反了 |
| 缺 `return` / `else` | `if` 判断正常执行 | 覆盖了不该覆盖的数据 |

**三个都不报错，输出还"看着挺像回事"。** 这才是静默错误最毒的地方——
你不会收到任何提示，只会在用到数据的下游才发现不对。

### 第 4 题（E43）· pandas 方法不接返回值 = 哑弹

**判定：❌ fail（连对 0/2）—— 本题空白，按规则判 fail。以下是补上的答案**

#### ① 错在哪

```python
df.sort_values(by='序号', ascending=False)   # ❌ 返回值没接住 → 哑弹
df = df[df["分数"] >= 60]                     # 这一行接了，所以过滤生效了
```

`df.sort_values(...)` **返回的是一张新表**，原表 `df` 一个字都没动。
你不接返回值，等于**把结果扔进了垃圾桶**——这一行长得像正经代码，实际效果是零。

实跑对比（同一份数据）：

```
--- 错误版（没接返回值）---
   姓名  序号  分数
0  张三   3   88
1  李四   1   95
2  王五   2   60        ← 顺序完全没变

--- 正确版（接返回值）---
   姓名  序号  分数
0  张三   3   88
2  王五   2   60        ← 按序号 3,2,1 排好了
1  李四   1   95
```

**为什么它危险**：`sort_values` **不报错、不警告、返回一张看起来完全正常的表**。
你要是写了 `df = df.sort_values(...)` 就对了；写成 `df.sort_values(...)` 就静默失效。
**唯一的区别是多一个 `df =`。**

#### ② 正确版本

```python
import pandas as pd

df = pd.DataFrame({
    "姓名": ["张三", "李四", "王五"],
    "序号": [3, 1, 2],
    "分数": [88, 95, 60]
})

df = df.sort_values(by='序号', ascending=False)   # ✅ 接住返回值
df = df[df["分数"] >= 60]                          # ✅ 这行本来就接了
df = df.drop(columns=["姓名"])                     # ✅ drop 也一样要接

print(df)
```

#### ③ 改完凭什么就"跑得对"了

因为 **pandas 的方法分两类**：

| 类别 | 例子 | 行为 |
|---|---|---|
| **返回新对象**（不接就没用） | `sort_values` / `drop` / `set_index` / `rename` / `reset_index` / `copy` | 原对象不变，结果在返回值里 |
| **原地修改**（不接也生效） | `fillna` / `inplace=True` 的那些 / `sort_index(inplace=True)` | 直接改原对象 |

实测三个哑弹方法：

```python
df.drop(columns=["分数"])          # 哑弹：原表列 = ['姓名', '序号', '分数']  ← 分数还在
df = df.drop(columns=["分数"])     # 接住：新表列 = ['姓名', '序号']

df.set_index("姓名")                # 哑弹：原索引 = [0, 1, 2]
df = df.set_index("姓名")           # 接住：新索引 = ['张三', '李四', '王五']
```

**三个哑弹方法**：`sort_values` / `drop` / `set_index`（还有 `rename` / `reset_index` 同理）。

**判据**：写完 pandas 的一行，**问自己"这个方法我接了吗？"**
`df.xxx(...)` 后面如果没有 `df = `，八成是哑弹。

> 💡 **为什么这题以前没人栽过？** 因为筛选那一行你**接了**（`df = df[df["分数"] >= 60]`），
> 而排序那行**没接**。两个长得几乎一样的行，一个接了一个没接——
> 所以错误不会报错，只会"看起来在干活"。

**判定：✅ pass（连对 1/2）—— ① 找到，② 缺函数体，③ 方向对**

你的作答：
```
①
findall 返回字符串列表、finditer 返回 Match 对象 —— 对 findall 的结果调 .group() 直接 AttributeError
②
改写后的代码：
for i in re.finditer(r'\d+', 文本):
③
换成finditer，.group()就可以
```

**① ✅ 找到核心**（虽然直接抄了题面标题，但结论对）。

**② ⚠️ 只写了 `for` 头，函数体没写。** 完整的应该是：

```python
import re

文本 = "订单A123已完成，金额456元，编号B78待发货"

for m in re.finditer(r'\d+', 文本):
    print(m.group(), m.span())
```

**③ ✅ 方向对**——"换成 finditer，.group() 就可以"，一句话点到本质。

#### 补充：两个函数的返回类型对比（实跑）

```python
re.findall(r'\d+', 文本)
# → ['123', '456', '78']        ← 字符串列表（list[str]）

for m in re.finditer(r'\d+', 文本):
    print(m.group(), m.span())
# → 123 (3, 6)
# → 456 (12, 15)
# → 78  (20, 22)                ← Match 对象（re.Match）
```

| 方法 | 返回什么 | 能调 `.group()` 吗 | 能拿位置吗 |
|---|---|---|---|
| `findall` | `list[str]` | ❌ AttributeError | ❌ |
| `finditer` | 迭代器，每次给一个 `re.Match` | ✅ | ✅ `.span()` |
| `search` | 单个 `re.Match` 或 `None` | ✅ | ✅ |
| `match` | 首个 `re.Match` 或 `None`（只从开头匹配） | ✅ | ✅ |

**选择规则**：
- 只想**拿到文本** → `findall`（最常用，最省事）
- 需要**位置 / 分组 / 匹配详情** → `finditer`
- **只要 `findall` 的结果又想要位置** → 用 `re.finditer` 就够，别去拼字符串查找

> 💡 **`re.Match` 对象上最常用的三个方法**：
> - `.group()` → 匹配到的文本（`.group(1)` 取第 1 个括号分组）
> - `.span()` → `(起点, 终点)` 元组
> - `.start()` / `.end()` → 单独取起点 / 终点

### 第 6 题（E36）· 判断条件查错对象：ch（键·字符）当成计数用 → TypeError

**判定：❌ fail（连对 0/2）—— 本题空白，按规则判 fail。以下是补上的答案**

> 📌 这题是**今天点名要复考的**：11-10 你手写第一版时就栽在这，
> 到现在**一次都没被任何一卷考过**——它 occ=1 排不进必考区、first_seen 又早于 7 天窗口进不了加练区。
> **这就是"自我饿死"：一道题如果没人考它，它就永远排不进来。**

#### ① 错在哪

```python
for ch in t:
    d[ch] = d.get(ch, 0) - 1
    if ch <= -1:          # ❌ 判断的是【字符】不是【计数】
        return False
```

`ch` 是**键**——一个字符（str）。`-1` 是**整数**（int）。
`str <= int` 这个比较 Python 不知道怎么比 → `TypeError`。

```
TypeError: '<=' not supported between instances of 'str' and 'int'
```

**你脑子里的想法是对的**：「计数变负了说明 t 里有多余字符」。
**但落笔落到了另一层**：计数不住在 `ch` 里，住在 **`d[ch]`** 里。

#### ② 正确版本

```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        d = {}
        for ch in s:
            d[ch] = d.get(ch, 0) + 1     # 遍历 s：加一
        for ch in t:
            d[ch] = d.get(ch, 0) - 1     # 遍历 t：减一
            if d[ch] < 0:                # ✅ 查的是【值】d[ch]，不是【键】ch
                return False
        return all(v == 0 for v in d.values())   # ← 补最终判定（原代码缺这行）
```

**两处改动，缺一不可**：

**改动 1：`ch` → `d[ch]`**
`d[ch]` 才是这个字符的**计数**（整数）。`ch` 是这个字符**本身**（字符串）。

**改动 2：补最终判定 `return all(v == 0 for v in d.values())`**

原代码注释里写着「这里还少了最终判定」，这行**不能省**。
`d[ch] < 0` 只能发现「t 里有多余字符」，**发现不了「s 里有多余字符」**。

实跑证明这行有多重要：

```python
# 只改 ch→d[ch]，但漏了最终判定
class 半吊子:
    def isAnagram(self, s, t):
        d = {}
        for ch in s: d[ch] = d.get(ch, 0) + 1
        for ch in t:
            d[ch] = d.get(ch, 0) - 1
            if d[ch] < 0: return False
        return True      # ← 漏了「所有计数必须归零」

半吊子().isAnagram("abc", "abc")   # → True ✅（碰巧对）
半吊子().isAnagram("aab", "abb")   # → False ✅（碰巧对，靠中途 return False 兜住）
```

**为什么说"碰巧对"**：这两个用例都能被中途的 `return False` 兜住，
但逻辑上缺了「s 有多余字符」这条防线——**你现在这个测试集测不出它**，
换个用例就露馅。完整版实跑：

```python
Solution().isAnagram("rat", "car")   # → False  ✅
Solution().isAnagram("aab", "abb")   # → False  ✅
Solution().isAnagram("abc", "abc")   # → True   ✅
Solution().isAnagram("ab", "ba")     # → True   ✅
Solution().isAnagram("ab", "abc")    # → False  ✅  ← s 有多余字符，半吊子版这里会返回 True
Solution().isAnagram("", "")         # → True   ✅
```

#### ③ 改完凭什么就"跑得对"了

**因为 `d[ch]` 和 `ch` 是两个不同层面的东西**：

| 写法 | 是什么 | 类型 | 例 |
|---|---|---|---|
| `ch` | **键**——字符本身 | `str` | `'r'` |
| `d[ch]` | **值**——这个字符的计数 | `int` | `3` |

Python 的字典就是「键 → 值」的映射：
- `d` 是**字典**
- `d[ch]` = **用键 ch 去查值** = 计数
- 想判断计数，就用 `d[ch]`

**判"某个东西是什么"的时候，先分清它在哪一层**：
是**键**还是**值**？是**元素**还是**容器**？

> 💡 **这类错有个通用识别法**：报错信息里出现
> `'<=' not supported between instances of 'str' and 'int'`
> → **几乎一定是「拿错了对象层级」**：
> 你要比较数量，却拿了名字/文本/标识符去比。
> 修法不是加类型转换（`int(ch)` 会得到垃圾值），
> 而是**往下一层找**——去 `d[ch]` 拿真正的计数。
