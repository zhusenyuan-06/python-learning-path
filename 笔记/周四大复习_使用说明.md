# 周四大复习 · 使用说明

> 这份是**给你自己看的操作手册**。每周四晚上照着做一遍就行。

---

## 一、这套机制解决什么问题

你说的话我翻译成了三个可执行的规则：

| 你的要求 | 机制里的实现 |
|---|---|
| 每周四都要大复习 + 查漏补缺 | 日程表 15 个周四晚上全部改成「大复习」槽位；每周四 19:00 自动触发 |
| 复习内容包括本周犯的错误 | 每题都记「犯过几次」，本周新错当场登记进池 |
| 上一周复习发现的问题要继续追 | 上一周没过关的题，连对计数没满，**下周四必然再出现** |
| 反复出现就一直复习到不再犯 | 连对 2 次才算掌握退场；再犯一次立刻抓回来，而且**通关门槛 +1** |

**关键设计**：一个错误不会因为"上次讲过了"就消失，它必须**连续两次答对**才能退出复习池。你越是反复犯同一个错，它就越是排在你复习卷的最前面。

---

## 二、每条错题的状态流转

```
        第一次犯 ─────→ 进池（active）
                          │
                          │ 每周四被抽到
                          ▼
                    答  对 │         答 错
                   ┌──────┴──────┐
                   ▼             ▼
              连对 +1        连对清零
              次数 +1        犯过次数 +1
                   │             │
              连对 = 2          （留在池里，
                   │              下周四优先）
                   ▼
             已掌握（mastered）
                   │
                   │ 日常练习中又犯了
                   ▼
             regress → 重新进池
             门槛 2 → 3 → 4（上限）
```

> 门槛会涨，是因为：**越容易反复的错，越要多次确认。**

## 三、每周四的操作步骤

### 第 1 步：生成复习卷（1 分钟）

```bash
cd /d D:\AI应用工程师\01-学习仓库-Python学习路径\pythonProject\笔记
"D:\AAAA\python.exe" 错题追踪器.py plan 6
```

会打印 6 道题，每题都有：
- ❌ 错在哪（代码片段）
- ✅ 应该怎么写（**先别看**，自己先改）

#### 取题规则（2026-10-29 改过）

| 部分 | 题数 | 规则 |
|---|---|---|
| 第一部分 · 必考区 | 4 | 按「犯过次数」降序取（老规则不变） |
| 第二部分 · 本周新错区 | 2 | 最近 7 天**新登记**的错题，固定占坑位；内部按「没被真正练过的优先」轮转 |

**总题数恒为 6**，两个区共享名额，不会变成 8 题。

> **为什么改？** 老规则只按「犯过次数」排序，而新错的次数一律 = 1。
> 池里只要还有犯过 ≥2 次的题，新错就永远排最后 → 进不了卷 → 没人复习
> → 次数不涨 → 永远排最后。**这是个自我饿死的循环。**
>
> 2026-10-29 实测：池里 27 题，`plan 6` 全被 10-21~10-28 的老高频题占满，
> 当天亲手犯的 E24~E28 **一道没进卷**。改成留 2 个坑位后才解决。
>
> 想关掉新错区（临时只练老题）：`plan 6 --no-new`

#### 新错区内部怎么轮转（2026-10-29 晚补）

新错区**不是**固定抽最新的两条。排序规则是：

1. **没被真正练过的排前面** —— 按「pass/fail 次数」升序（`pending` 不算，
   题发出去了但没作答 = 没练过）
2. 同样没练过的，按登记日期**新的排前面**

> **为什么不能只按「最新」排？** 只按最新排 → 每周抽到的都是同一批
> （E24、E25）→ 等 7 天窗口一滑，这批连同其余 12 条一起过期 →
> **「一次都没被抽到过」的新错一次都没被考过** —— 换了个形式的自我饿死。
>
> 加上「练过次数」当第一排序键后：没练过的先上，练过的往后排，
> 14 条新错大约 7 周轮完一轮。

### 第 2 步：做题（主体，60-90 分钟）

按题目顺序，**一题一题**来：
1. 只看 ❌ 那段代码，**自己说出哪里错**、**自己改写**
2. 改完对照 ✅ ，讲清楚为什么
3. 特别针对**高频题**（犯过 ≥2 次）——这类题答错不丢人，但必须当场改对

### 第 3 步：记录结果（每题 1 条命令）

```bash
# 答对了
"D:\AAAA\python.exe" 错题追踪器.py record E02 pass "知道是入参被覆盖了"

# 答错了
"D:\AAAA\python.exe" 错题追踪器.py record E03 fail "又忘了 strip"
```

命令输出会告诉你下一次的状态：
- `连对 1/2` → 下周还要考
- `连续答对 2 次 → 已掌握，退出复习池` → 这题暂时毕业了
- `又犯了。连续答对清零` → 下周排在高频区

**如果复习卷出了、但你还没作答**（比如当天没空做），记一笔"待答"，连对计数不动：

```bash
"D:\AAAA\python.exe" 错题追踪器.py pending E02 "复习卷已出，待作答"
```

> 为什么要有这条：题目发出去了但没作答，**不算对也不算错**。
> 如果直接记 pass，追踪器就会虚报进度；直接记 fail 又不诚实（你根本没试）。
> `pending` 保持 streak 不变，等你真写了再 record。这条规则从 2026-10-22 起生效。

### 第 4 步：登记新错（顺手做）

这周写新代码遇到的、清单里没有的错误：

```bash
"D:\AAAA\python.exe" 错题追踪器.py add "标题" "错误写法" "正确写法" "标签1,标签2"
```

### 第 5 步：收尾

```bash
"D:\AAAA\python.exe" 错题追踪器.py render    # 重新生成 错题追踪.md
"D:\AAAA\python.exe" 错题追踪器.py stats     # 看池子还剩几题
```

## 四、命令速查

| 命令 | 作用 |
|---|---|
| `ls` | 列出所有待复习题（按优先级排序） |
| `stats` | 统计概览 + 顽固问题 TOP |
| `plan N` | 生成 N 题复习卷（默认含 2 个新错坑位，总题数 = N） |
| `plan N --no-new` | 关掉新错区，只考老题 |
| `show E01` | 看某题的详情 + 复习流水 |
| `add` | 登记新错题 |
| `record ID pass/fail` | 记录复习结果 |
| `pending ID` | 复习卷已出、还没作答时记一笔（**不动连对计数，不虚报**） |
| `regress ID` | 已掌握的题又犯了 → 抓回来 |
| `render` | 重新生成 `错题追踪.md` |

## 五、文件说明

| 文件 | 作用 | 需不需要你手改 |
|---|---|---|
| `笔记\错题追踪.json` | **数据源**，所有错题状态都在这 | 不用，用命令改 |

**只有 `错题追踪.json` 是真的**，`错题追踪.md` 随时可以删了重生成。

## 七、给自己的三条提醒

1. **别只记不练**——记下来但下周四没做，等于没记。每周四的 `plan` 是硬指标。
2. **答错不丢人，答错不记才丢人**——`record ... fail` 才是这套系统的燃料。
3. **静默错误优先**——报错型错误 Python 会拦你，静默型（缺 `reverse=True`、缺 `.strip()`、缺 `else`）没人拦，所以它们排在前面。
