## 一、总骨架：五步套路（两天一个字没改）

```python
import sqlite3
from pathlib import Path

库路径 = Path(__file__).parent / "数据" / "新闻库.sqlite"

con = sqlite3.connect(库路径)                        # ① 连上
cur = con.cursor()                                   # ② 拿话筒
cur.execute("SELECT ... FROM 新闻 WHERE ... GROUP BY ...")   # ③ 说 SQL（只改这句）
结果 = cur.fetchall()                                # ④ 收结果
con.close()                                          # ⑤ 关电话
return 结果                                          # ⚠️ 必须 return
```

### 子句执行顺序（背下来，LIMIT 永远最后）

```
WHERE  →  GROUP BY  →  HAVING  →  ORDER BY  →  LIMIT
筛行      分堆        筛组      排序        截断
```

### 2.2 参数化 `?` 与元组传值

`?` 有几个，值就得有几个，且**必须用元组包起来**。

```python
# 一个占位符
cur.execute("SELECT COUNT(*) FROM 新闻 WHERE 星期 = ?", ("星期二",))

# 两个占位符
cur.execute("SELECT 序号 FROM 新闻 WHERE 星期 = ? AND 序号 > ? ORDER BY 序号 ASC",
            ("星期一", 5))

# 单元素元组 —— 逗号不能漏
cur.execute("SELECT COUNT(*) FROM 新闻 WHERE 新闻内容 LIKE ?", ("%金融%",))
```

## 三、11-18 复盘：GROUP BY / COUNT / AS / ORDER BY / LIMIT / HAVING

| 题 | 骨架 | 实跑结果 |
|---|---|---|
| 1 | `GROUP BY 星期 ORDER BY 星期 ASC` | 7 行：`('星期一',3) ('星期三',1) ('星期二',2) ('星期五',2) ('星期六',4) ('星期四',1) ('星期日',2)` |
| 2 | `COUNT(*) AS n` + `ORDER BY n DESC, 星期 ASC` | `('星期六',4) ('星期一',3) ('星期二',2) ('星期五',2) ('星期日',2) ('星期三',1) ('星期四',1)` |
| 3 | 同上 + `LIMIT 3` | `('星期六',4) ('星期一',3) ('星期二',2)` |
| 4 | `WHERE 序号 <= ?` + `GROUP BY` | 6 行：`('星期一',2) ('星期三',1) ('星期二',2) ('星期六',3) ('星期四',1) ('星期日',1)` |
| 5 | `ORDER BY n ASC, 星期 ASC LIMIT 1` | `[('星期三', 1)]` |
| 6 | `HAVING COUNT(*) >= ?` | 5 行（滤掉星期三、星期四） |
| 7 | `HAVING` + `ORDER BY` + `LIMIT 1` | `[('星期六', 4)]` |

**`AS n` 的作用**：给聚合列起别名，`ORDER BY` 才能引用它。

### fetchall() 返回形状

| SELECT 列数 | fetchall() 返回 | 要不要压平 |
|---|---|---|
| 一列 | `[('值',), ...]` | ✅ 要：`[行[0] for 行 in 结果]` |
| 两列 | `[('星期一', 3), ...]` | ❌ 不用压平 |
| 单个聚合 | `[(15,)]` | `cur.fetchone()[0]` |

> 铁律：**元组长度 = 你 SELECT 了几列**。
> 11.17 练习（8 题）几乎全是「一列 → 压平」；11.18 练习（7 题）全是「两列 → 不压平」。

## 四、五个必踩的坑（2026-11-19 实跑复现）

### 坑 1 · ORDER BY 并列时顺序【不确定】 → 必须加次级排序键

同一份数据，两条只差一个次级键：

```sql
-- 只写主键
SELECT 星期, COUNT(*) AS n FROM 新闻 GROUP BY 星期 ORDER BY n DESC
→ [('星期六',4), ('星期一',3), ('星期日',2), ('星期五',2), ('星期二',2), ('星期四',1), ('星期三',1)]

-- 加次级键
SELECT 星期, COUNT(*) AS n FROM 新闻 GROUP BY 星期 ORDER BY n DESC, 星期 ASC
→ [('星期六',4), ('星期一',3), ('星期二',2), ('星期五',2), ('星期日',2), ('星期三',1), ('星期四',1)]
```

**3 个「2 条」的星期（星期二 / 星期五 / 星期日），两种写法顺序真的不同。**
SQL 只说了「按 n 降序」，没说「n 一样时按什么排」→ 那一档由数据库自己决定。

> 📌 讲义 11-18 当天写的是「这次碰巧一样，但不敢保证下次一样」。
> 11-19 实跑直接跑出了差异 —— 这就是活证据。

**防法**：`ORDER BY n DESC, 星期 ASC`（主键 + 次级键，顺序完全确定）。

### 坑 2 · 中文排序按【字符编码】排，不是「星期几」

```sql
SELECT 星期 FROM 新闻 GROUP BY 星期 ORDER BY 星期 ASC
→ [('星期一',), ('星期三',), ('星期二',), ('星期五',), ('星期六',), ('星期四',), ('星期日',)]
```

**星期三 排在星期二 前面。** 编码实测：

| 星期 | 末字 | 编码 |
|---|---|---|
| 星期一 | 一 | 0x4e00 |
| 星期三 | 三 | 0x4e09 |
| 星期二 | 二 | 0x4e8c |
| 星期五 | 五 | 0x4e94 |
| 星期六 | 六 | 0x516d |
| 星期四 | 四 | 0x56db |
| 星期日 | 日 | 0x65e5 |

数据库只认编码大小，不懂「周一到周日」的语义。
**防法**：想要真正的星期顺序 → 自己加一列数字 1-7 再 `ORDER BY`，别指望中文直接排。

### 坑 3 · WHERE 筛【行】，HAVING 筛【组】，位置不能换

```sql
-- 错①：该用 HAVING 却写成 WHERE
WHERE COUNT(*) >= ?  ... GROUP BY 星期
→ OperationalError: misuse of aggregate: COUNT()

-- 错②：HAVING 放到 GROUP BY 前面
... HAVING COUNT(*) >= ? GROUP BY 星期
→ OperationalError: near "GROUP": syntax error
```

**判断口诀**：条件里的东西「分堆前就有」→ WHERE；「分堆后算出来」→ HAVING。
- `序号 <= 10` → 行上有这列 → WHERE
- `COUNT(*) >= 2` → 条数是组算出来的 → HAVING

### 坑 4 · 单元素元组漏尾逗号

```python
cur.execute("SELECT 序号 FROM 新闻 WHERE 新闻内容 LIKE ?", ("%金融%"))
→ ProgrammingError: Incorrect number of bindings supplied.
  The current statement uses 1, and there are 4 supplied.
```

**为什么报「4」？** 字符串是可迭代对象，`"%金融%"` 有 4 个字符 → Python 当成 4 个绑定值传进去，SQL 只要 1 个 → 数量对不上。

```python
cur.execute("SELECT 序号 FROM 新闻 WHERE 新闻内容 LIKE ?", ("%金融%",))
→ ✅ 正常，命中 [(2,)]
```

**防法**：`?` 的值默念「逗号、括号、逗号、括号」；单元素必带逗号。

### 坑 5 · 抄上一题的 SQL，SELECT 后面必须重看一眼

```sql
-- 对
SELECT 序号, 星期 FROM 新闻 GROUP BY 星期 ORDER BY 星期 ASC LIMIT 3
→ [(5,'星期一'), (9,'星期三'), (7,'星期二')]

-- 错：SELECT 抄成了 COUNT(*)
SELECT COUNT(*) FROM 新闻 GROUP BY 星期 ORDER BY 星期 ASC LIMIT 3
→ [(3,), (1,), (2,)]
```

**语法完全合法，不报错、不警告，但逻辑全错** —— 最难查的一类错，因为它【静默】。

**防法**：抄题时把 `SELECT` 当独立的一行重新念一遍，别跟着 `FROM` 一起复制。

> ⚠️ 附带坑：SQLite 允许 GROUP BY 时 SELECT 选没分组的列（上面第一行就选了 `序号`），
> 但 MySQL 开 `ONLY_FULL_GROUP_BY` 会直接报错。别依赖这个宽松行为。

## 五、pandas ↔ SQL 对照（最值钱的一页）

| pandas | SQL |
|---|---|
| `df["星期"].unique()` | `SELECT DISTINCT 星期` |
| `df.groupby("星期").size()` | `GROUP BY 星期` + `COUNT(*)` |
| `.sort_values(ascending=False)` | `ORDER BY n DESC` |
| `df.head(3)` | `LIMIT 3` |
| `df[df["序号"] <= 10]` | `WHERE 序号 <= 10` |
| `df.groupby("星期").size()[lambda s: s >= 2]` | `GROUP BY 星期 HAVING COUNT(*) >= 2` |

## 六、今天真正要记住的 8 件事

1. 五步套路不变，只改 `execute` 里那句 SQL
2. 子句顺序 `WHERE → GROUP BY → HAVING → ORDER BY → LIMIT`
3. `WHERE` 筛行 / `HAVING` 筛组，位置不能换
4. `ORDER BY` 并列时顺序不确定 → 加次级排序键
5. 中文排序按编码，不是按语义
6. `?` 的值必须元组，单元素带尾逗号
7. 抄题时 `SELECT` 单独重看一眼
8. 元组长度 = SELECT 列数 → 决定要不要压平
