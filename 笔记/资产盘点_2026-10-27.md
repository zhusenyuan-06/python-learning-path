## 十六、🔧 怎么自己复核这些数字（不用靠别人）

盘点最怕「凭记忆写数字」。下面 4 条命令可以在 Git Bash 里直接跑，随时刷新资产视图。

### 1️⃣ 文件总数 + 目录分布
```bash
cd /d/pythonProject
git ls-files -z | tr '\0' '\n' | awk -F/ '{if(NF==1)print "根目录";else print $1"/"}' | sort | uniq -c | sort -rn
```
> 当前结果：笔记/ 30、根目录 26、projects/ 3 → **合计 59**

### 2️⃣ Python 文件数与行数
```bash
git ls-files -z | tr '\0' '\n' | grep -c '\.py$'          # 文件数
git ls-files -z | tr '\0' '\n' | grep -E '^[^/]+\.py$' | wc -l   # 根目录
git ls-files -z | tr '\0' '\n' | grep -E '^笔记/.*\.py$' | wc -l # 笔记/
```
> 当前结果：全部 38、根目录 23、笔记/ 15

### 3️⃣ 中文文件名必须加 `core.quotepath=false`
```bash
git -c core.quotepath=false ls-tree --name-only HEAD
```
> 不加这个参数，`默认参数 & 关键字参数.py` 会被显示成八进制转义 `\351\273\210...`，
> 肉眼核对会以为文件乱了。**这是今晚踩过的坑（见工具链坑 T07）。**

### 4️⃣ 含空格的文件名 → 别用 `for f in $(...)`
```bash
for f in $(git ls-files ...); do wc -l < "$f"; done    # ❌ 拆词，漏统计
while read -d "" f; do wc -l < "$f"; done < <(git ls-files -z)   # ✅
```
> `默认参数 & 关键字参数.py` 会被拆成 3 个词，循环里报 "No such file or directory"。
> 今晚因此把 23 个根目录 .py 数成了 22 个。**见工具链坑 T08。**

### 5️⃣ 本地 vs 远端差异
```bash
git log --oneline origin/main..HEAD     # 待推送的 commit
git diff --stat origin/main..HEAD       # 待推送的文件变化
```

### 6️⃣ ⭐ 别只盘仓库 —— 仓库外的资产最容易漏
这次盘点的**三个大发现全在仓库外**（技能清单 xlsx / 幼儿园菜项目 / SQL 教材）。
扫一遍 D 盘和桌面：
```bash
ls -1 /c/Users/15816/Desktop/                      # 桌面全部
find /d -maxdepth 2 -type d -not -path "*/\.*"       # D 盘两层目录
```
> ⚠️ **只 `ls Desktop` 是不够的** —— 桌面上的 `.zip` 得解开看才知道里面是什么。
> 这次就是解开 `幼儿园菜汇总工具.zip` 才发现 `D:\AI应用工程师\02-作品-幼儿园菜汇总工具\幼儿园菜\` 有 1843 行源码。
> **压缩包是资产黑洞**：文件名不告诉你里面有没有真东西。

### ⚠️ 为什么必须用 `-z`
`git ls-files` 默认输出会把路径里的中文和空格用引号包起来转义，
直接 `wc -l` 数出来的行数不等于真实文件数 —— **统计前统一加 `-z`（NUL 分隔）再转换**。
今晚因为这个，根目录 .py 一开始被数成 0 个，修正后是 23 个。

### 💡 盘点纪律
