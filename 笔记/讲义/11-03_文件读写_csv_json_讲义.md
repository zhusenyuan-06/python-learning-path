## 一、今天真正学到的 5 件事

### 1. `open()` 返回的是"门"，不是内容

```
open(path, "r")  →  文件对象 f（一扇门）
f.read()         →  门后的内容（一个字符串）
f.readlines()    →  门后的内容（一个列表，每行一个元素）
for line in f    →  一次拿一行
```

**⚠️ 同一个 `f` 只能顺序读一次。** `read()` 读完指针就停在末尾，再 `readlines()` 拿到的是**空列表**。

> 这条我今天踩了 **2 次**。

### 2. `with` = 帮你自动关门

`with` 块一缩进结束，文件就关了。**所以块外再用 `f` 会报 `ValueError: I/O operation on closed file`。**

> `with` 的本质是 `try/finally` 的语法糖 —— 会写 `finally` 之后，回头看 `with` 就明白它为什么这么设计。

### 3. pathlib：路径全程是"对象"，不是字符串

| API | 作用 |
|---|---|
| `Path(".")` | 当前目录 |
| `Path(__file__)` | **当前这个 .py 文件** |
| `.parent` | 上一级目录 |
| `/ "名字"` | 拼路径（**不要用 `+`**） |
| `.glob("*.py")` | 按模式找文件（返回**生成器**，要 `len(list(...))`） |
| `.exists()` | 在不在（**方法**，有括号） |
| `.name` / `.stem` / `.suffix` | 文件名 / 无扩展名 / 扩展名（**属性**，没括号） |
| `.stat().st_size` | 文件大小（字节） |
| `.mkdir(parents=True, exist_ok=True)` | 建目录 |

**⚠️ 属性 vs 方法**：`p.exists()` 有括号，`p.name` 没括号。写错**不报错**，但逻辑全错 —— 静默错误。

### 4. csv：格子只能放一个字符串

- `newline=""` 写和读**都要**加，否则 Windows 上多空行
- 读回来**全是字符串**，排序要 `int()`
- 列表要先 join：`"|".join(条["tags"])`
- **嵌套分隔符不能等于外层分隔符**（csv 里的逗号 vs 我自己定义的 `|`）

### 5. 异常处理：写清楚"哪种错"

```python
try:
    可能出错的代码
except 具体异常类:      # ← 必须具体，不能光写 except:
    处理
finally:
    无论如何都执行
```

**TypeError = 类型都不对；ValueError = 类型对但值不合理。**

**顺带修了 3 个 bug**（都是"程序没崩但结果是错的"）：

- `done 999` 会打印"已完成第 999 条"（其实一条都没改）—— **返回值被丢弃**
- `done -1` 会真的改掉最后一条 —— **Python 负数索引不报错，是最后一条**
- `isinstance(n, int)` 挡不住 `True` —— **bool 是 int 的子类**

**核心改动：返回值设计统一**

```python
# 改前：成功返回列表，失败返回字符串 → 类型不统一，调用方没法判断
def mark_done(tasks, n):
    if n < 1 or n > len(tasks):
        return f"错误：n 必须在 1~{len(tasks)} 之间"
    ...
    return tasks

# 改后：永远返回 (成功标志, 消息)
def mark_done(tasks, n):
    if n < 1 or n > len(tasks):
        return False, f"错误：编号必须在 1~{len(tasks)} 之间"
    ...
    return True, f"已完成第 {n} 条"

# 调用方：tuple unpacking，无脑解包
成功, 消息 = mark_done(tasks, n)
if not 成功:
    print(消息)
    continue
```
