## 三、三个库怎么打开 PDF（同一个文件，三种写法）

```python
# PyPDF2
reader = PyPDF2.PdfReader(路径)
n = len(reader.pages)                    # 页数
text = reader.pages[0].extract_text()    # 第 1 页文字

# pdfplumber —— 必须用 with
with pdfplumber.open(路径) as pdf:
    n = len(pdf.pages)
    text = pdf.pages[0].extract_text()
# 出了 with 块，文件才真的关闭

# pymupdf —— 不会自动关，要自己 close()
doc = pymupdf.open(路径)
n = doc.page_count
text = doc[0].get_text()                 # 注意是 get_text，不是 extract_text
doc.close()
```

**三处最容易记错的：**

1. `pymupdf` 是 `get_text()`，另两个是 `extract_text()` —— **方法名都不一样**
2. `pdfplumber` 必须 `with`；`pymupdf` **反而不自动关**
3. `pymupdf` 的页数属性叫 `page_count`（属性），另两个是 `len(...)`（方法）

## 四、⭐⭐⭐ 三个库的真实差异（全部本机实测，别背）

| | PyPDF2 | pdfplumber | pymupdf |
|---|---|---|---|
| 取第 1 页文字 | `pages[0].extract_text()` | `pages[0].extract_text()` | `doc[0].get_text()` |
| **98 页耗时** | **24~27 秒** | **46~48 秒** | **0.77~0.8 秒** ⚡ |
| 页眉「第1页，共8页」 | ✅ 保留 | ❌ **丢掉** | ✅ 保留 |
| 空格处理 | 无空格 | 无空格 | 保留空格 |
| 空文本页返回 | `''` 空串 | `''` 空串 | `''` 空串 |
| 知道页面有没有图 | ❌ | ❌ | ✅ `get_images()` |
| 提表格 | ❌ | ✅ 要页面真有表格线 | ❌ |
| 关键词定位 | ❌ | ❌ | ✅ `search_for()` |

**pymupdf 比 PyPDF2 快 29~35 倍，比 pdfplumber 快 45~65 倍。**

> ⚠️ **秒数每次跑都不同**（机器负载、磁盘缓存），所以写区间。**倍数才是稳定结论。**

> 💡 **为什么快这么多**：PyPDF2 和 pdfplumber 是纯 Python 逐个字符解析，pymupdf 是 C 写的 MuPDF 库。
> **PDF 有几百页时，这个差别就是「能不能跑完」的差别。**

### ⚠️ 三个库提取的文本**不完全一样**

同一页（第 1 页），实测：

```
PyPDF2    : '第1页，共8页1、当某个分组在输出链路发'    ← 748 字符
pdfplumber: '1、当某个分组在输出链路发送时，从发送第'   ← 794 字符
pymupdf   : '第1 页，共8 页\n1、当某个分组在输出链'     ← 777 字符
```

**→ 所以断言绝对不能写 `extract_text() == 期望字符串`** —— 换个库就挂。

只能这么断言：

```python
assert "时延" in text          # 比关键词
assert 700 < len(text) < 900  # 比长度区间
assert 页数 == 8               # 比页数
```

## 五、⭐ 五个坑（全部本机实测出来的）

### 坑 1 · 空结果长得不一样

| 情况 | PyPDF2 | pdfplumber | pymupdf |
|---|---|---|---|
| 这一页没文字 | `''` 空串 | `''` 空串 | `''` 空串 |
| **文件打不开** | `PdfReadError` | `PDFSyntaxError` / `FileNotFoundError` | `pymupdf.FileNotFoundError` |

→ **判断「这页没文字」要用长度判断，不要用 `is None`**：

```python
if len(text.strip()) == 0:     # ✅ 对
    ...
if text is None:               # ❌ 抓不到空串
    ...
```

### 坑 2 · ⭐⭐⭐ 扫描图片页提取不到文字（今天最大的坑）

**实测：《大学物理实验（一）》讲义.pdf 共 98 页，其中 44 页提取不到文字。**

那些页是**扫描图片** —— 页面里只有一张图，没有嵌入字体，PDF 的「文字层」是空的。

```

第 2页  文字1835字  图片1张
第 3页  文字 141字  图片0张
第 4页  文字   0字  图片1张  ← 扫描页（无文字层）
第 5页  文字   0字  图片2张  ← 扫描页
```

**扫描页区间：第 4 页 ~ 第 47 页（连续 44 页）**

怎么认出扫描页：

```python

```

**真实项目里这类页要靠 OCR**（本机没装 `pytesseract`）。

> ⚠️ **「能打开、能读页数」≠「每页都有文字」。**
> 写提取代码前，先跑一遍逐页统计：有文字几页 / 空文本几页。

### 坑 6 · ⭐⭐⭐⭐ 验证时别拿「全文 ==」当判据（我自己今天踩了）

### 坑 6 · ⭐⭐⭐⭐ 验证时别拿「全文 ==」当判据（我自己今天踩了）

做完练习后我用 pdfplumber 独立重算，「拼全文」这题判不一致：

```
pymupdf 拼出来    5400 字符
pdfplumber 拼出来 5462 字符   ← 差 62
```

差点以为是答案写错了。查下去发现真相：

| 检查 | 结果 |
|---|---|
| 去掉所有空白后的长度 | **4878 vs 4878 —— 完全相同** |
| 每个字符的出现频次 | **一个字都不多不少 —— 完全相同** |
| 差别在哪 | **页眉「第1页，共8页」在每页的开头还是结尾** |

→ **内容完全等价，只是排版顺序不同。**

**正确判据**：

```python
import re
from collections import Counter

def 归一(文本):
    文本 = re.sub(r'第\d+页，共\d+页', '', 文本)   # 去页眉页脚
    return Counter(''.join(文本.split()))          # 去空白 + 字符多重集
```

`归一(A) == 归一(B)` ✅

**→ 这就是 T38 的翻版：验证工具的判据本身也会错。**
**看到不一致时，先怀疑【判据】，再怀疑【被验证的对象】。**

## 七、⭐ 落库：提取出来不存下来等于没做

```python
import sqlite3

con = sqlite3.connect("库文件.sqlite")
cur = con.cursor()
cur.execute("CREATE TABLE 页文本 (页码 INTEGER, 文字 TEXT)")
for i in range(doc.page_count):
    cur.execute("INSERT INTO 页文本 (页码, 文字) VALUES (?, ?)",
                (i + 1, doc[i].get_text()))     # ⚠️ 用 ? 参数化
con.commit()          # ⚠️ 不 commit，关闭连接时数据回滚
行数 = cur.execute("SELECT COUNT(*) FROM 页文本").fetchone()[0]
con.close()
```

**三个坑（承接 SQL 讲义二的实测结论）：**

1. 不 `con.commit()` → 关连接时数据**回滚**（行数变 0）
2. 路径写错 → `sqlite3.connect` **静默创建一个 0 字节假库**，不报错
3. `with sqlite3.connect()` **只管事务不管关连接** → 要既提交又关闭用 `contextlib.closing`

> SQLite 的函数名是 `LENGTH()`，不是 Python 的 `len()`：
> `SELECT 页码, LENGTH(文字) FROM 页文本` ✅

## 八、pymupdf 独有的两个能力

另两个库都做不到，但做 RAG 的时候很有用：

```python
# ① 找关键词在页面上的位置（坐标）
pg.search_for("时延")
# → [Rect(105.72, 80.94, 129.72, 92.93), Rect(279.72, 80.94, 303.72, 92.93)]

# ② 按块/按词提取（带坐标）
pg.get_text("blocks")   # → 29 个块，元素是 (x0, y0, x1, y1, 文字, ...)
pg.get_text("words")    # → 69 个词，元素是 (x0, y0, x1, y1, 词, ...)
```

用途：按版面还原、只取某块内容、定位「第几页第几行提到了某个关键词」。
